### HTTP、浏览器和部署验证

Browser 插件在本次会话不可用，采用固定 Playwright 1.58.2。实际浏览器为 Chromium 145.0.7632.6、Firefox 146.0.1，均 headless、`en-US`，视窗 1440×900 与 390×844；Chromium 禁用 GPU，Firefox 使用默认设置。显式设置 locale 避免测试环境中 Firefox 的原生页面国际化异常。窄视窗不代表移动浏览器验证。

根路径与 `/jellyfin` 分别在新建隔离实例执行真实 HTTP、入口部署和两个浏览器的完整流程：

- 匿名及普通用户不能调用管理接口；普通用户仅能请求有播放权限的媒体，撤销权限后已生成缓存也返回拒绝。检查分页、参数校验、任务状态与空上传位置、跨会话和跨媒体冲突、重启后的 410。
- 真实 socket 中断未完成上传，验证任务失败并释放位置；完整发送请求但不读取响应，另行查询接收成功后断开，再次提交同一位置复用任务。覆盖实际传输故障，不仅依赖服务层注入。
- 管理页面四区切换、配置保存及非法顺序拒绝、恢复默认数值；上传、异常第二页与整批确认、绑定/生效/停用、原文件下载哈希、解绑及删除。
- 三种显示模式确有渲染；暂停画布不变、倍速和向后跳转、控制区 DOM 重建不重新加载集合；桌面和窄屏设置面板边界通过。截图已检查。画中画只模拟进入/退出事件验证清理与恢复，不声称画中画窗口显示已验收。
- 离开页面立即取消待返回的会话查询和播放请求，迟到响应不能覆盖新页面；自动失败不重复请求，手动重试、410 提示及恢复成功；退出登录释放资源、同浏览器换用户偏好隔离。禁用或脚本不可用时原播放器继续工作。
- 入口重复生成、非根路径、未知自定义入口拒绝、撤销和容器重建、保留数据的插件卸载重装均通过。镜像变更测试使用基于 12.1 添加入口探针的派生镜像，验证重新提取及回退流程；这不证明另一个 Jellyfin 版本的兼容性。

浏览器无未处理的 Danmuku 页面异常。原生登录前 WebSocket 连接失败、无 Chromecast 环境警告及故障注入的 503/410/404 保留在证据中；原生 TanStack 导航取消按精确来源单独记录，不作为插件异常，也不笼统忽略其他页面错误。

每种路径、每个浏览器连续进入/退出 20 次。每轮结束 Canvas、监听器、动画帧、观察器、请求、集合及活动弹幕均归零，仅保留全局适配器的一个定时器。以下为第一轮与第二十轮结束值，RSS 是浏览器进程树合计，不是插件专属内存：

| 路径 / 引擎 | JS 堆（字节） | 浏览器 RSS（KiB） |
| --- | --- | --- |
| 根路径 / Chromium | 22,147,494 → 23,477,750 | 852,812 → 970,360 |
| 根路径 / Firefox | 引擎不提供该接口 | 1,102,588 → 1,148,284 |
| `/jellyfin` / Chromium | 23,089,082 → 24,177,417 | 856,796 → 959,752 |
| `/jellyfin` / Firefox | 引擎不提供该接口 | 1,110,176 → 1,158,896 |

Chromium 每轮在相同受控 GC 条件下记录堆，Firefox 结合资源计数和 RSS 趋势。上述有限次数没有发现插件活动资源累积，不据此承诺任意时长或所有浏览器的内存恒定。

### 性能测量条件与边界

正式矩阵使用同一 3,700 秒 H.264 视频（640×360、24 fps、504,649,941 字节），SHA-256 为 `c230c1ff372a0766ab5f13a58f72284d4046b61e30e8f6ea36172dc7bb3165e3`。测试环境为 x86_64、.NET SDK 10.0.112、Node 24.20.0；服务容器限制单 CPU、1 GiB，浏览器任务限制一个逻辑 CPU，重度任务串行。视频只读挂载，无生产数据。

每种配置和视窗分别进行 20 次新播放标识加载、20 次设置响应、20 次跳转重建、20 次进入退出，以及弹幕关闭/开启各连续 10 分钟。加载不复用同一个播放标识的重试缓存；首次应用选择单独记录，不称为操作系统磁盘冷启动。掉帧同时检查实际播放时间、解码帧数和弹幕渲染量，避免空画布取得无效结果。同屏值为配置上限，实际峰值由布局及防碰撞规则决定，结果分开记录。
