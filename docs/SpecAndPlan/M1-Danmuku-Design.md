## 1. 目标与范围

### 已确认范围

M1 为 Danmuku 插件实现完整使用流程：管理员导入本地弹幕文件，将其绑定到影片或剧集单集，通过管理页面管理弹幕，用户播放时能够看到弹幕并控制开关。

M1 的播放展示支持范围为 Jellyfin Web 浏览器端，其他客户端的弹幕播放支持不纳入 M1。接入方式见第六章。

M1 正式支持范围为桌面 Chrome、Edge、Firefox；不支持画中画模式的弹幕，不为画中画增加独立渲染、窗口同步或控制界面。移动浏览器和 Safari 暂不纳入正式验收。

M1 必须支持真实样本 `BV1zCtq61Eoi.xml` 和 `BV1zCtq61Eoi.json` 所代表的两种弹幕格式，不将支持范围泛化为任意 XML 或 JSON。

切分、合并及时间轴对齐功能放到 M2，不在 M1 实施。M2 的具体设计和实施计划另行讨论。

## 2. 用户流程

### 已确认规则

- 每个视频可绑定多个弹幕文件，同一时间最多一份生效，由管理员在管理页面切换生效文件。
- 无弹幕时不显示任何提示。
- 弹幕加载失败时需要提示用户，但不影响视频播放。
- 首次导入自动生效；追加导入保留当前生效文件，由管理员手动切换。
- 解除当前媒体的生效文件绑定时，要求管理员选择另一份已绑定文件生效，或明确选择停用弹幕；解除非生效文件绑定不影响当前选择。文件本体只能在无任何媒体引用后另行删除，解除绑定不自动删除文件。
- 管理员在播放过程中切换生效文件，下次开始播放时使用新选择，当前播放保持原文件。
- 加载失败使用自动消失的非阻塞提示，同一次播放不重复弹出。

### 完整流程

1. 管理员进入弹幕管理页面，选择影片或剧集单集，上传本地弹幕文件。
2. 插件校验并解析文件，显示导入结果；失败时提供明确原因，成功后将弹幕绑定到所选媒体。
3. 管理员可查看媒体绑定的多个弹幕文件，切换唯一生效文件、替换或解除当前媒体的绑定；文件本体仅在无引用时另行删除。生效选择遵循上述规则，替换完成条件见第五章替换契约。
4. 有权播放该媒体的用户在 Jellyfin Web 播放时加载对应弹幕，可手动开关；暂停、继续和跳转进度时，弹幕跟随播放器当前进度。
5. 无弹幕时不显示任何提示；弹幕加载失败时使用自动消失的非阻塞提示，同一次播放不重复弹出，两种情况均不影响视频正常播放。

上述随播放进度同步属于正常播放行为；M2 的时间轴对齐指编辑弹幕时间以适配不同视频版本，例如整体偏移或分段校准，具体定义待后续确认。

## 3. 数据模型与存储

### 已确认规则

- 保留上传的原始文件，同时保存标准化后的弹幕数据，便于播放读取，并为 M2 的切分、合并和时间轴对齐保留来源。
- 原始文件与解析数据存放在 Danmuku 插件自己的数据目录，不写入媒体目录，不与 AgentBridge 共享存储。
- 允许同一份弹幕文件绑定多个视频，每个视频独立选择生效文件。
- 从某个视频移除绑定，只影响该视频；删除文件本体时，若仍有媒体绑定则阻止删除，并显示引用情况。

### 已确认的数据组织

- 弹幕文件：独立 ID、原始文件名、服务器留存文件名、显示名称、格式、内容哈希、导入时间、条目数、最后一条弹幕的出现时间及解析数据版本。最后一条弹幕的出现时间不视为视频时长；原始文件名保留上传时的名称，服务器留存文件名记录重名处理后的实际名称。
- 弹幕条目：插件内部条目 ID、源弹幕 ID（字符串）、出现时间（毫秒）、文本、颜色、原始显示模式及字号；源 ID 不作为跨文件唯一键。保留来源格式及源条目顺序，以便追溯原始数据。
- 来源附加信息：保留源发送时间、发送者哈希，以及 JSON 的 `weight`、`attr`、原始数值 `id` 或 XML 的池字段；缺失字段不臆造。M1 仅将附加字段用于来源追溯，不用于自动评分、筛选或用户识别，不赋予未验证的含义。
- 媒体绑定：使用 Jellyfin 媒体条目 ID 关联弹幕文件 ID，不以媒体路径或名称作为绑定主键；每个媒体最多选择一个已绑定文件生效，也可停用。
- 文件替换：为当前媒体指定被替换文件 A，上传 B 并解析；内容未存在时创建新文件，完全相同内容优先复用已有文件 ID。发布时一次提交移除 A 的绑定、绑定 B 及所需生效变更，保留 A 文件本体及其在其他媒体上的引用；不得将普通追加导入成功视为替换完成。具体生效和冲突规则见第五章。

### 已确认的存储方案与数据生命周期

- 使用 Danmuku 独立 SQLite 数据库保存文件元信息、标准化弹幕条目、媒体绑定和生效选择；原始文件单独存放于插件数据目录。同名不同内容时自动添加文件名后缀，服务器实际留存文件名也使用加后缀后的名称，不仅修改管理页面显示。文件关联使用独立文件 ID，不依赖文件名。
- 生效切换、绑定更新等数据库变更使用事务；数据库约束保证生效文件属于当前媒体已绑定文件。原始文件与数据库之间的写入不视为同一个事务：先暂存并校验文件，再完成持久化与数据库登记，失败时恢复或清理，未完成导入不得成为生效数据。恢复流程见本章全文审阅补充。
- 解除最后一个媒体绑定后仍保留文件，供后续复用；管理员可筛选并手动删除未绑定文件，不自动清理用户导入的数据。
- Jellyfin 媒体条目消失后保留原绑定并标记失效，供管理员重新绑定或解除；不按同名或路径自动匹配新条目。检测时机见本章已确认的恢复与失效检查规则。
- 插件升级保留数据并维护数据库结构版本；涉及结构迁移时先备份，迁移失败不得以空库覆盖原数据。禁用或卸载插件不主动删除业务数据。

选型依据：SQLite 官方将应用本地存储列为适用场景，并提供事务能力。此处采用 SQLite 是结合本插件独立部署、媒体关联及生效切换需求确认的设计选择；驱动与打包原则见本章全文审阅补充，具体固定版本及包清单在实施计划中列明并验证。参考 [SQLite 适用场景](https://www.sqlite.org/whentouse.html) 与 [事务说明](https://www.sqlite.org/transactional.html)。

### 已确认的恢复与失效检查

- 导入采用暂存、校验、发布三个阶段，只有完整保存原始文件、解析数据和绑定关系后才报告成功。导入失败或进程中断不得改变已有生效选择；再次启动时核对未完成任务，清理能够确认属于失败任务的暂存数据，不删除已完成导入的未绑定文件。无法确认归属的数据保留并记录待处理问题。
- 在管理员打开相关媒体的绑定详情、执行绑定或切换操作时检查媒体条目是否存在；同时提供管理员手动检查全部绑定的操作。M1 不进行后台周期性全库扫描。媒体查询失败时标记检查失败，不将其误判为媒体已删除。
- 每次播放加载的弹幕数量有上限，不要求加载完整文件的所有条目；这项用户后续确认的约束取代此前完整弹幕快照方案。当前播放仍固定使用开始播放时选定的文件版本，后续切换、替换或删除不影响当前播放。有限条目的筛选、加载方式及版本保留机制在第六章确定。

### 全文审阅补充：持久化结构与发布恢复

- 使用 `Microsoft.Data.Sqlite` 直接访问独立 SQLite，不引入共享数据库或运行时 Core。所有 SQL 参数化；写入由有界后台任务协调，不把驱动的 `Async` 方法当作异步磁盘 I/O。官方依据：[驱动概述](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/)、[异步限制](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async)。实施计划锁定具体 NuGet 版本，并将必要托管及原生运行时依赖纳入 Danmuku 发布包；不借用 Server 未承诺提供的内部依赖。
- 数据目录由 Jellyfin 应用数据路径解析，包含数据库、原始文件、任务暂存、迁移备份和可清理的播放重试缓存；不硬编码 Docker 路径。数据库不放在只读媒体目录或依赖网络共享锁语义的路径。
- 主表为 `Files`（文件元信息与状态）、`Comments`（文件 ID、源序号及标准化字段）、`MediaBindings`（媒体 ID 与文件 ID 联合唯一）、`MediaState`（媒体 ID、可空生效文件 ID、是否主动停用、版本号）、`ImportBatches`、`ImportSlots`（批次位置及接收状态）、`ImportTasks`、`ImportErrors`、`PlaybackRequests` 和结构版本表。文件版本使用不可变文件 ID；替换仅在上传内容此前不存在时创建新 ID，完全重复内容优先复用已有 ID。媒体状态不随解除最后一个绑定自动删除，以保留主动停用状态。
- 约束保证生效文件属于该媒体绑定集合；索引覆盖文件内容哈希、`(FileId, TimeMs, SourceOrdinal)`、媒体引用及任务异常分页。源 ID 不作为唯一键，重复条目保留。存储时间为非负 64 位整数毫秒，缺失来源字段可空。
- 发布前将原文件及标准化暂存结果完整落盘，登记可恢复的发布意图及目标名称；按文件锁和数据库唯一约束处理重名与重复内容。文件移动到正式位置后，以数据库事务一次登记文件、条目、绑定、生效选择和任务完成状态。正式查询只读取已发布记录，事务失败不改变原绑定。
- 重启按任务意图和事务结果核对：已提交则恢复完成；未提交则仅清理能证明属于该任务的文件。删除无引用文件时先事务检查并标记删除，再移除磁盘文件并完成记录清理；磁盘删除失败保留可重试状态，不将失败报告为成功。并发新绑定不能引用正在删除的文件。
- 全局限制上传、解析及发布并发，使用流式 XML/JSON 解析和有界缓冲；异常明细写入任务存储后分页读取，不在内存收集全部条目。具体队列容量、资源预算和运行时依赖清单属于实施计划参数，必须列明并测试，不改变本设计的用户限额。

- 为两种结构分别提供解析器，转换到第三章的统一数据模型；依据内容结构校验格式，不能只看扩展名。
- XML 秒值按十进制转换为毫秒，超出毫秒精度时按本章字段兼容规则四舍五入；JSON 直接读取整数毫秒。
- 保留模式、字号与颜色；M1 播放展示须覆盖样本中的 `1`、`4`、`5` 三种模式，呈现契约见第六章。
- JSON 优先取非空 `idStr`，缺失时按本章字段兼容规则回退。XML 源 ID 按字符串保存。
- 原始文件完整保留；标准化模型不要求两种格式具有完全相同的附加字段，也不丢弃原始来源信息。
- 两份样本应分别验证导入，并核对条目数及关键字段；不能将它们当作完全相同数据的两个序列化版本。

导入交互、重复文件处理、错误策略及媒体绑定细节见本章以下规则。

### 已确认的重复文件与异常处理

- 完全相同的文件按原始字节内容哈希识别并复用已有文件记录。普通首次/追加导入时，尚未绑定当前媒体则创建绑定，已绑定则提示已存在，不重复创建；首次绑定自动生效、追加绑定不改变当前生效选择，已主动停用不因重复上传而重新启用。替换同样优先复用已有内容，但按第五章替换契约更新绑定与生效选择，不套用普通追加规则。
- 文件名相同但内容不同的文件作为独立文件导入，不覆盖旧文件，并自动添加文件名后缀；服务器实际留存文件名也添加后缀。原上传文件名保留在元信息中。XML 与 JSON 不进行跨格式语义去重。
- 文件整体无法解析或不符合支持的结构时，拒绝导入并显示原因，不改变已有绑定或生效选择。
- 可解析文件中的个别异常条目或暂不支持的显示模式不静默丢弃：展示有效条目数、异常条目数及原因，并提供“跳过全部异常条目并导入”按钮，管理员一次点击即可放弃这些异常条目的标准化导入并保存正常条目，无需逐条确认；同时提供取消该文件导入的入口。原始文件完整保留；没有有效条目时拒绝导入。
- 批量导入时，提供“跳过本批全部异常条目并继续导入”入口，一次操作处理本批已完成校验、等待确认的文件；各文件分别报告正常导入数、跳过数及原因。该操作不能绕过文件大小、条目数上限或整体解析失败，不能导入全为异常条目的文件，也不会重复导入已成功处理的文件。普通条目遵循既有绑定与生效规则。
- 文本作为纯文本处理，不执行其中的 HTML 或脚本；XML 解析禁用 DTD 与外部实体。

异常条目、支持模式、缺失字段、批量操作及导入上限按本章对应的已确认规则处理。

### 已确认的文件命名与导入操作范围

- 重名后缀放在扩展名前，依次使用 ` (1)`、` (2)` 等，例如 `example.xml`、`example (1).xml`。在 Danmuku 留存原始文件的目录内检查名称冲突并选择可用名称，不覆盖既有文件；同内容复用优先于重命名。
- 上传文件名仅取基础文件名并清理路径分隔符及不安全字符；独立文件 ID 始终作为内部关联依据。管理页面显示服务器留存文件名，并可查看原上传文件名。
- 一次导入可选择多个 XML/JSON 文件，各文件独立校验并显示结果；部分失败不撤销其他文件的成功导入。存在需确认的跳过条目时，仅相应文件等待确认。
- 导入目标为管理员明确选择的单个影片或单集；支持从已有文件列表选择文件进行绑定，不自动按文件名匹配媒体。
- 无绑定记录的媒体首次批量导入时，以用户提交列表中首个成功完成导入并绑定的文件作为生效文件，按列表顺序处理，不取决于并发完成先后；已有生效文件或已主动停用的媒体保持原选择。

### 已确认的字段兼容与异常条目规则

- M1 接收并展示模式 `1`、`4`、`5`；其他模式保留在原始文件中，计入不支持条目，沿用管理员确认后导入有效条目的规则，不擅自转换成其他模式。
- 时间和非空白文本为必要字段。时间必须是有限、非负且可保存为毫秒整数的数值；XML 秒值用十进制转换，超出毫秒精度时四舍五入（中点向远离零方向），JSON 的 `progress` 要求为整数毫秒。时间晚于当前视频时长的条目仍保留，播放时不会提前显示。
- 显示模式、字号、颜色缺失时分别默认使用 `1`、`25`、白色（`16777215`），并在导入结果中报告使用默认值的条目数；字段存在但类型或取值不合法时不静默修正，计入异常条目。字号要求为正整数，颜色为 `0`–`16777215` 的整数。
- 源 ID、发送时间、发送者哈希、权重及属性不作为播放必填字段。JSON 优先保留非空 `idStr`；缺失时将整数 `id` 的原始数字文本作为回退来源并报告回退，不宣称能够恢复已有精度损失。两者均缺失时源 ID 留空，插件生成内部条目 ID；XML 源 ID 缺失时同样处理。
- 附加元信息缺失或无法解释不阻止有效播放条目导入；原始文件保留原值，标准化附加字段无法解析时留空并报告。未知扩展字段不导致整文件失败。
- 不要求输入按时间排序；标准化条目按时间排序，同一时间按源条目顺序稳定排列。不根据文本、时间或源 ID 自动删除重复条目。

XML `p` 字段通过固定位置解释，缺失尾部可选字段可接受，缺失中间字段须保留逗号占位，不猜测错位字段含义。渲染字号约束见第六章。

### 已确认的导入限制

- 每文件最多 300,000 条源条目，包含将被跳过的条目。单文件大小上限为 50 MiB（52,428,800 字节）。条目数与字节数是独立限制，不保证任意 300,000 条数据都能在大小上限内导入。超过任一文件级限制时拒绝整个文件，不截断导入；已成功导入的其他文件不受影响。
- 已确认：单条文本最多 100 个 Unicode 码点，超出时计入异常条目，不截断文本；按已确认的异常条目确认流程处理。普通汉字、字母、标点和空格通常各计一个码点，组合 emoji 可能包含多个码点；不按 UTF-8 字节数或 UTF-16 代码单元数计数。真实样本最长文本为 100 个码点，符合此上限。
- 已确认：一批最多选择 10 个文件；前端逐文件上传处理，不把全部文件合并到一个请求中。超出批量数量限制时提示调整选择，不自动截取前 10 个。
- M1 暂采用固定上限，管理页面在导入前说明限制，不提供上限配置项。
- 尚无性能测试证明最大数据量的承载能力；实施验证须覆盖边界输入、超过上限的拒绝行为，以及从最大允许数据量中按播放上限选取弹幕后的浏览器加载与播放。如验证表明需要调整，须更新设计并确认变更。

## 5. API 与权限

### 已确认的权限边界

- 管理接口仅限 Jellyfin 管理员，包括导入、文件列表与原文件下载、绑定管理、生效切换、删除及失效检查。
- 播放接口要求 Jellyfin 用户认证，并校验当前用户对目标媒体的访问与播放权限；只返回当前媒体对应的受限播放数据，不允许凭文件 ID 绕过媒体授权。
- 播放响应仅包含渲染所需字段，不返回发送者哈希、源发送时间、原始文件路径等来源或存储信息。
- 业务接口沿用 Jellyfin 认证，不新增独立账号或插件专用共享密钥，拒绝匿名访问；仅固定前端资源和最小公开引导状态允许匿名读取，见全文审阅补充。
- 普通用户的弹幕开关只影响自己的播放，不修改管理员配置的生效文件。
- 弹幕加载数量上限由服务端执行，客户端不得通过修改请求参数绕过；防止重复或分段请求绕过每次播放总量限制的契约在第六章确定。

### 已确认的操作流程与错误反馈

- 导入采用任务流程：上传后返回任务 ID；界面仅展示关键阶段、百分比进度及统计摘要，不逐条展示正常弹幕，也不逐条输出处理日志。全正常文件自动完成导入，需要跳过异常条目的文件进入待确认状态，由已确认的一键操作继续。未完成的文件不建立正式绑定或改变生效选择。
- 导入摘要包括各文件状态、已处理条目数、正常条目数、异常条目数，以及完成后的实际导入数与跳过数；进度按关键阶段表达，具体百分比计算口径在接口契约中定义，不能在尚未完成保存时宣称导入完成。
- 仅异常条目通过列表展示，支持服务端分页，默认每页 50 条；返回异常总数及分页信息，不将全部异常先发送到浏览器后再做客户端分页。列表可定位源条目并说明异常原因。
- 异常列表分页不改变一键跳过的作用范围：单文件操作涵盖该文件的全部异常，本批操作涵盖本批已完成校验且待确认文件的全部异常，不仅处理当前页，也不要求逐页查看后才能继续。
- 对同一导入任务重复提交确认只返回已有结果，不重复创建文件或绑定；对同一媒体重复绑定同一文件同样不重复创建关系。任务 ID 不替代管理员授权，每次操作均校验权限。
- 绑定与生效选择携带版本号。两个管理员同时修改同一媒体时，基于旧版本的修改返回冲突，提示刷新后重试，不静默覆盖另一人的修改。
- 无生效弹幕返回正常的空结果，前端不提示。未登录、无媒体权限、目标不存在、文件过大、校验失败、状态冲突和服务异常分别返回可识别的错误；面向用户的信息说明原因及下一步操作，响应不暴露服务器路径或异常堆栈。
- 播放加载失败沿用第二章的非阻塞提示规则，不影响视频播放；管理操作失败保留现有生效状态，允许用户修正输入或刷新后重试。

- 播放响应仅包含状态、媒体与文件版本标识、加载上限、选定条目数、显示配置和渲染条目；条目包含内部 ID、毫秒时间、文本、显示模式、颜色和字号，不返回来源元信息。无绑定、已停用或 Web 支持关闭时返回正常空结果，不造成用户提示。
- 错误使用稳定业务代码与可读信息：未登录为 401，权限不足为 403，不存在为 404，版本或状态冲突为 409，字节超限为 413，不支持的文件格式为 415，字段或条目上限校验失败为 422，内部失败为 500。先校验权限再返回敏感对象详情；客户端按错误代码处理，不解析错误文案。
- 上传完成并被接收的任务返回 202；任务包含 `stage`、可为空的 `stagePercent`、已处理/正常/异常/导入/跳过条目数、状态与到期时间。待确认等非进度阶段不伪造百分比；确认和取消接口按已有任务状态幂等返回结果。

批量发布顺序见本章，播放重试标识和 Web 入口更新规则见第六章。上述接口约定已确认，不表示已经实现。

### 全文审阅补充：缺失接口与配置字段

- 新增 `POST /Danmuku/Imports/{taskId}/Resume`，接收刷新后明确确认的 `expectedVersion`，恢复绑定冲突任务；版本仍不匹配继续返回 409，不隐式覆盖。替换任务保留原 `replaceFileId` 意图，并再次确认目标仍绑定；目标已解除则提示取消该任务后重新选择目标，不降级成普通追加。
- 新增公开只读 `GET /Danmuku/Web/BootstrapState` 及固定静态资源路径 `/Danmuku/Web/Assets/{assetName}`，仅提供启用标志、资源版本和随插件发布的白名单资源。此例外仅用于已确认的引导方案；业务接口仍要求认证，资源路径不接受任意磁盘路径。
- 播放接口携带 `playbackId`，响应增加请求到期时间与算法版本。已过期返回 410，缓存容量暂不足返回 503；响应按用户隔离并禁止共享缓存。全局停用返回正常状态，用户权限被撤销返回 403。
- 管理员配置字段包括 `WebEnabled`、三档时长加载上限、四档同屏保护上限；保留现有 `InstanceLabel`。业务数据不放入配置 XML。首次安装 `WebEnabled` 默认关闭，管理员完成入口部署后明确启用。
- 用户本地偏好按服务器标识与用户 ID 隔离，保存开关、密度档、区域、不透明度和字号缩放；退出登录后其他用户不得继承同一份偏好。用户选择的密度只保存档位，不保存管理员当时的具体条数。

### 已确认的批量发布顺序与并发修改

- 上传和校验按文件列表推进，前面的文件等待异常确认不阻止后面的文件继续上传、校验和展示摘要；正式保存及绑定则按用户提交的文件顺序推进。
- 前序位置尚未接收完成或等待确认时，后续已校验文件显示“等待前序文件处理”，不提前改变绑定或生效选择。前序位置或任务进入完成、失败、取消、过期、中断之一后继续；未成功导入的位置不占首次生效名额，未上传位置也必须按下述收尾规则结束。
- 批量一键跳过仅处理该批已完成校验且待确认的文件；尚未校验完成的文件之后发现异常仍需确认，不把一次点击当作对未来未知异常的持续授权。
- 创建批次时记录目标媒体绑定版本；本批成功发布后更新本批预期版本，避免与自身的连续写入冲突。若期间其他管理员或另一个批次修改该媒体绑定，后续绑定提交返回冲突，不覆盖新配置。
- 版本冲突不要求重新上传或解析。任务进入待处理状态，管理员刷新并查看当前绑定后选择“按当前绑定继续”或取消；普通导入按当前状态应用首次/追加规则，替换按下述替换契约保留原目标并重新校验，不恢复过时的生效选择。
- 冲突待处理沿用异常待确认的 24 小时保留规则，从首次进入等待状态计时，不因反复刷新延长。已经成功发布的文件和绑定不因本批后续冲突或取消而回滚。

### 审阅修订：替换意图与原子提交

- 复用现有批次、上传、确认和恢复接口，不新增替换接口。创建批次携带 `operation`（默认 `append`，替换为 `replace`）；替换必须提供当前媒体已绑定的 `replaceFileId=A`，且只登记一个上传位置，明确 B 替换 A。任务持久化该意图，上传、异常确认和冲突恢复均不丢失目标。
- B 校验完成或通过跳过异常确认后，才进入替换发布；尚未发布时 A 的绑定及生效选择保持不变。最终发布事务校验媒体版本和 A 仍被绑定，将当前绑定集合中的 A 移除并加入 B，再按下表决定生效选择；B 已绑定时仅保留一份关系。与文件发布及任务完成状态一并提交，成功后才显示“替换完成”。

| 提交时当前媒体状态 | 替换 A 为 B 后 |
| --- | --- |
| A 生效 | B 生效，其余绑定保留 |
| A 非生效，另一文件 C 生效 | C 保持生效，其余绑定保留 |
| 媒体已停用或无生效文件 | 保持停用/无生效状态，不因替换自动启用 |

- 原始字节完全重复优先复用已有文件 ID，不因替换强制创建新 ID；B 与 A 相同时，版本与目标校验通过后作为无内容变化的成功返回，不改绑定、生效状态或文件。A 文件本体始终保留，其他媒体引用不变，无引用后可另行删除。
- 校验、发布失败或版本冲突时，不应用部分绑定修改，不把“文件校验完成”报告为“替换完成”。版本冲突时 B 的新内容作为任务暂存保留，沿用 24 小时待处理规则；失败、取消或到期则按原有规则清理任务暂存。已有 B 的正式记录不受影响，清理不能删除复用的正式文件。
- 冲突恢复使用刷新后的版本和当前绑定状态；原 A 仍绑定时，按表重新计算生效选择，保留其他管理员的新状态。A 已不再绑定时不能继续该替换，需取消后重新选择目标。恢复不得改为普通追加或重新套用冲突前的生效选择。

### 审阅修订：上传位置状态与批次收尾

- 创建批次即持久化所有位置，初始为 `PendingUpload`，即使尚无导入任务也可查询、取消或到期；开始上传后转为 `Receiving`。只有完整接收并持久化文件后，才原子转为 `Accepted` 并登记唯一任务 ID。`Accepted` 位置随后以对应任务的状态决定是否结束。
- 无法完整接收的请求（例如断连或上传超限）将该位置记为失败并清理能确认归属的部分文件，不留为永久接收中；同一位置的接收完成、失败和取消必须互斥。若只是响应丢失而服务端已完成接收，则保持已接收状态并返回原任务 ID，不因客户端未收到响应取消它。
- 从未开始上传的位置有等待接收截止时间，从批次创建起计时；接收中的位置另有从接收开始计时的有限请求期限。两个超时参数在实施计划固定，不能以是否打开管理页决定，也不能无期限续期；到期分别标记过期或失败并收尾。它们与异常/冲突确认的 24 小时期限相互独立。
- 批次取消默认处理所有未完成位置，也可以携带 `slots` 仅处理指定位置；尚无任务 ID 的位置照样取消。终结位置不能重新上传或复活，需要重传的文件另建批次；重复上传已接收位置不创建第二个任务。
- 某位置未上传、上传中断或取消，不撤销其他已接收任务，不因页面关闭取消服务端任务。该位置终结后，后续已校验任务按原列表顺序发布，首个真正成功发布的文件占首次生效名额。
- 全部位置终结后，批次转为已结束并记录 `finishedAt`，汇总成功、失败、取消、过期、中断数量；“批次已结束”不等于所有文件成功。空缺位置不得从统计中消失，也不得令批次永久进行中。批次状态及最多 10 个位置的摘要随按批次查询的任务列表返回。

### 已确认的导入任务取消与保留

- 关闭或刷新管理页面不取消服务端已接收完成的任务；重新进入任务列表后可查看进度及处理待确认异常。尚未上传完成的文件不承诺续传，位置按收尾规则结束后需重新创建批次上传，不复用已终结的位置。
- 单文件任务支持取消，批量取消覆盖尚未完成的任务及没有任务 ID 的上传位置；按指定位置取消也使用批次取消接口。不撤销已经成功导入的文件。取消与接收完成、最终发布均按原子状态转换确定结果，迟到请求不能复活终结位置或任务；界面如实显示结果，不将已成功导入的数据作为临时数据清理。
- 等待确认跳过异常的任务保留 24 小时，从进入待确认状态开始计时；到期取消并清理暂存数据，不影响正式文件及既有绑定。界面显示到期时间。
- 完成、失败、取消、过期、中断均为不可重新运行的终态，进入时记录 `finishedAt`。任务摘要与异常明细保留 7 天，从 `finishedAt` 开始计时，不因重启或查看而重置；批次结束后其位置摘要也保留 7 天。清理运行记录不删除已导入文件、标准化条目或绑定。
- 服务重启后核对持久化完成状态，已发布任务恢复为已完成，其余未完成任务和未接收完成位置标记中断并记录终态时间，清理能够确认归属的暂存数据，由管理员重新导入；不自动续跑。再次重启不重置原终态时间。清理失败记录原因，不影响既有生效弹幕。


### 已确认的进度展示与完成状态

- 界面显示当前阶段和该阶段百分比，不伪造跨阶段统一百分比。上传阶段按已上传字节数 / 文件总字节数；解析校验阶段按已消费输入字节数 / 文件总字节数；保存阶段按已处理有效条目数 / 待保存有效条目总数计量。
- 解析校验阶段即使输入已读完，在结构结束校验、统计和异常结果持久化完成前保持低于 100%；保存阶段在文件发布、绑定和数据库事务提交完成前保持低于 100%。最终只有完成状态显示导入成功。
- 等待异常确认、排队、取消、失败和中断显示明确状态，不显示持续增长的虚假进度。每阶段使用独立标签，例如“解析校验 60%”，切换阶段可从 0% 开始。
- 进度接口返回摘要及阶段进度，不返回逐条正常弹幕；批量汇总显示已完成文件数 / 总文件数，不把各文件百分比直接平均成总进度。

## 6. 管理页面与播放展示

已确认：每次播放加载的弹幕数量有上限，不加载或展示全部导入条目。单文件可导入 300,000 条是存储与导入边界，不是播放加载目标。

### 按时长分档的播放加载上限

已确认：按视频时长分档决定每次播放最多加载的条目数，并提供管理员修改各档条数的配置项。

| 视频时长 | 默认每次播放加载上限 |
| --- | --- |
| 小于 30 分钟 | 5,000 条 |
| 30 分钟至 60 分钟（含 30 和 60 分钟） | 8,000 条 |
| 超过 60 分钟 | 10,000 条 |

恰好 30 分钟和恰好 60 分钟均归中档；三档条数由管理员配置，M1 的时长分界点固定。

已确认的配套规则：

- 服务端使用 Jellyfin 媒体时长决定分档，不接受客户端指定时长绕过上限，不用最后一条弹幕出现时间代替视频时长；无法取得可靠时长时使用三档配置中的最小上限。
- 设置保存后作用于新开始的播放；当前播放固定开始时的配置及文件版本。可用条目少于该档上限时加载实际数量；暂停、跳转及重复请求不会增加本次播放选定的条目总数。
- 超过上限时按视频时间范围分配名额并在有弹幕的区间筛选，尽量覆盖整段视频，不直接截取最前面的 N 条。具体算法见下文已确认的超量弹幕筛选，不以语义或 AI 评分作为 M1 依赖。

已确认的配置校验：各时长档加载上限为 1–20,000 的整数，要求短、中、长三档非递减；低、中、高、重叠四档同屏保护上限为 1–600 的整数，要求四档非递减；默认 100／200／400／600，低／中占用预算固定为 40%／65%，详见第八章。非法值或顺序在管理页面和服务端均拒绝，保存失败不改变原配置；提供恢复默认入口。30 万条仅作为文件导入上限。管理员提高配置后的性能需以最大 20,000 条加载、重叠档 600 条同屏另外验证，不将默认配置的性能结果外推。

### 已确认的超量弹幕筛选

- 将视频时间轴按 1 分钟划分区间，末段可不足 1 分钟；只对有可播放弹幕的区间分配名额。已知视频时长时不选择超过视频时长的条目，但保留这些条目的存储记录；时长未知时按实际弹幕时间划分区间，不以此推断视频时长或改变加载档位。
- 以各非空区间均衡分配为起点，区间条目少于名额时全部选入，剩余名额继续分给尚有余量的区间，直到达到加载上限或候选条目耗尽；不保证每个区间在名额少于非空区间数时都能获得名额。
- 每个区间内采用固定种子的伪随机抽样，不总是取该分钟最早的条目。种子及稳定排序基于媒体 ID、文件版本和内部条目标识，不依赖两种格式不一致的数值源 ID；不使用未明确语义的 `weight` 字段排序。
- 余数名额及名额不足时的区间选择同样采用确定性抽样，避免每次偏向视频开头。同一媒体、文件版本、时长、加载配置和筛选算法版本得到相同集合；不同播放不额外随机换一批。
- 选定后按出现时间和源条目顺序稳定排序供播放，拖动进度只定位同一集合，不重新抽样。条目筛选不会改写原始文件、标准化数据或弹幕出现时间。

### 已确认的同屏显示与用户设置

- 每位用户可在播放器中开关弹幕并调整显示密度；加载上限由管理员控制，显示设置只影响当前用户的渲染，不改变媒体绑定或其他用户的播放。
- 提供低、中、高、重叠四档，默认高。低／中采用预计面积 40%／65% 预算，高／重叠不另限面积比例；默认同屏保护为 100／200／400／600 条，滚动、顶部和底部合计。前三档防碰撞，重叠档只允许涉及滚动的重叠。管理员配置四档保护上限，用户仅选择档位；上下间距不随密度变化。计算、配置、生命周期及验收按第八章执行，实际性能仍需验证。
- 轨道不足或达到同屏上限时跳过当前无法展示的条目，不排队延迟到后续时间播放，避免弹幕与视频内容错位；加载的条目不保证全部显示。
- 显示区域按视频画面高度分四档，选项直接显示 `25%`、`50%`、`75%`、`100%`，默认 `75%`；区域从画面顶部向下延伸。不透明度默认 75%，字号缩放默认 100%，均可由用户调整；保留原始字号差异，缩放范围见下文已确认的播放行为细节。
- 默认开启弹幕；记住用户最后一次开关及显示设置，按 Jellyfin 用户和浏览器本地保存，同一浏览器换视频继续沿用，M1 不提供跨设备同步。无弹幕时不提示，有弹幕加载失败时仍遵循既定提示规则。

### 已确认的播放行为细节

- 用户关闭弹幕后立即清空画面并停止渲染，再次开启时从当前视频进度恢复，不补播关闭期间的内容；沿用本次已选集合，不重新抽样或增加加载总量。
- 暂停时弹幕同步停住，继续时同步恢复；拖动进度时清除旧画面，定位同一选定集合中的新时间位置，恢复该位置应显示的内容，不补播跨过的弹幕。
- 顶部、底部及滚动弹幕都限制在所选显示区域内；底部弹幕贴所选区域的下边缘，而不是始终贴视频画面底部。
- 用户修改密度、显示区域、不透明度和字号时立即作用于当前播放。管理员修改四档同屏保护上限时仅影响新开始的播放，当前播放保留开始时的配置。
- 不透明度提供 10%–100% 调节，步长 5%；字号缩放提供 50%–200% 调节，步长 10%。窄屏布局、全屏及窗口尺寸变化时重新计算轨道，无法容纳的条目按已确认规则跳过。

M1 不支持画中画弹幕，不接管或扩展浏览器画中画窗口。仅验证桌面浏览器页面、全屏和窗口尺寸变化；窄屏适配不表示移动浏览器已纳入支持范围。不为画中画开发单独的渲染与同步协议。

### Jellyfin Web 接入

已确认的产品行为：管理员在 Danmuku 配置页启用 Web 弹幕支持后，访问本服务器 Jellyfin Web 的用户在原播放器中获得弹幕开关与设置入口，不要求每个用户安装浏览器扩展或脚本管理器；只提供 Danmuku 自身固定的前端资源，不提供任意脚本执行配置。管理页显示接入状态和故障原因，接入失败不影响原视频播放。禁用后移除用户可见的弹幕入口并保留已导入的数据；运行中页面的撤销时机及彻底卸载步骤见下文。

已检查的工程条件：当前插件仅通过 `IHasWebPages` 暴露管理配置页，尚无播放器接入代码；开发 Compose 使用官方镜像及非 root 用户，未配置 Web 目录可写挂载。现有配置页能力不能作为播放器脚本已自动加载的证据。

目标官方镜像的 Web 入口权限已做只读检查：不应假定非 root 服务用户可修改镜像内 Web 资源。部署方案由外部工具生成入口挂载，具体 Web 路径和服务身份按目标环境解析，不以某台开发主机的 UID/GID 为前提。

参考实现中存在修改 Web `index.html` 引入脚本的方式，并明确指出容器文件权限可能阻止写入，见 [Custom JavaScript 插件维护者说明](https://github.com/johnpc/jellyfin-plugin-custom-javascript)。这仅是技术调研依据，不代表已验证本仓库目标版本兼容性，也不引入该插件为依赖。

开发测试实例与正式 Jellyfin 实例相互独立。正式部署工具显式接收目标镜像、配置目录、Web 路径及 Base URL，不以开发主机或仓库开发实例作为默认正式目标；开发脚本仅管理仓库隔离资源。

接入选择采用下述已确认的入口挂载方案，保留不维护 Server/Web fork、不跨插件依赖的约束。文件更新方式及运行中页面的撤销行为如下；具体兼容性验证作为实施计划的首项技术验证，失败时回到设计修订，不擅自引入其他插件或 Web fork。设计确认时尚未实施注入代码；后续实现与验证状态见验证记录。

已确认的部署与撤销规则：

- Docker 部署允许一次性增加本项目管理的 Web 入口文件挂载，保留非 root 运行；入口以当前镜像原版为基础，只追加带 Danmuku 标识的加载标记，不替换播放器资源包，不改宿主 Docker 配置。生成和升级流程见下文全文审阅补充，实施时必须验证。
- 部署生成入口时仅增加本插件固定标记，重复生成不重复插入；日常启用/禁用仅修改配置，彻底撤销才移除标记。前端资源加载失败不得阻塞原播放器启动。
- 镜像升级时从新镜像重新取得对应入口并重新应用加载标记，不继续使用旧版入口覆盖新版。检测到无法识别的入口结构时停止接入并在管理页说明问题，不覆盖未知内容。
- 正常卸载流程先撤销 Web 接入，再卸载插件；直接在 Jellyfin 中卸载导致插件无法执行清理时，由仓库卸载工具处理残留入口标记。刷新页面后确认弹幕入口已移除。
- 此部署设计已确认，但不代表已完成兼容性验证；播放器入口生成、挂载及脚本接入尚未实施。

测试重部署授权：M1 测试允许清理和重部署本仓库隔离开发容器。执行时仅操作 `jellyfin-forge` 开发与隔离测试资源，保持 `http://127.0.0.1:18096`，不改端口、不停止其他项目服务、不修改宿主 Docker 配置；保留已有 config/cache/media 数据目录，授权不包含删除持久化数据。实施须在设计及实施计划整体审阅通过后取得用户明确授权，再按计划执行自动化验证和人工测试。

### 已确认的部署入口与功能开关分离

部署保留固定引导入口，日常功能开关仅修改插件配置；禁用后不再出现弹幕控件的体验保持不变。

- 部署时在当前镜像的原版入口中加入固定的 Danmuku 引导脚本标记，挂载后的入口文件可按只读方式提供给容器；日常启用、禁用只修改插件配置，不写 Web 入口文件。
- 引导脚本只负责读取最小的公开启用状态，启用后才加载完整前端资源并注册播放器控件。公开响应仅包含启用标志和静态资源版本，不返回业务数据、用户信息、服务器路径或详细故障。原有管理和播放接口权限不变。
- 配置关闭、插件不可用或状态检查失败时，引导脚本安静退出，不增加弹幕控件，不阻止 Jellyfin Web 启动。业务播放请求失败仍遵循播放页面反馈规则，不与引导阶段混淆。
- 普通禁用保留固定引导标记；彻底撤销 Web 接入或卸载时，由仓库部署工具移除该标记并重新部署挂载。镜像升级仍从新镜像原版入口重新生成，不复用旧版入口覆盖新版。
- 设置页区分“已部署入口”“功能已启用”“待刷新/需重新部署”和故障状态，避免开关已保存却误报浏览器已经接入成功。已打开播放页的行为仍遵循已确认规则，不新增推送或轮询。

此规则已确认并替换此前运行时启用/禁用直接增删入口标记的做法；当前尚未执行任何文件挂载或注入变更。

### 全文审阅补充：入口生成与播放器适配

- 仓库部署工具从指定镜像提取对应原始 `index.html`，记录镜像标识、原始哈希、生成哈希和 Base URL；仅向可识别位置加入版本化的异步同源引导资源。生成目录位于忽略的开发数据或 artifacts 中，不提交完整第三方 Web 产物。
- 在宿主生成临时文件并校验，再原子替换宿主管理文件；创建或重建本仓库容器以使单文件只读挂载指向新文件。不要求插件在容器内原子替换挂载文件，不通过放宽整个 Web 目录权限解决问题。生成失败保留旧部署，不启动部分生成的入口。
- 镜像升级从新版原始入口重新生成；旧入口保留用于回退。检测到人工修改造成哈希不一致时停止覆盖并提示处理，保留其他自定义内容。撤销 Web 接入后恢复对应版本原入口或移除挂载并重建容器；不停止其他项目服务。
- 独立的 Web 适配层负责获得当前媒体 ID、视频元素、播放器容器及播放生命周期，渲染层只消费视频时钟和有限条目集合。离开视频页、退出登录或切换媒体时撤销事件与画面，迟到异步响应按播放 ID 丢弃；只适配本服务器提供的目标版本 Web。
- 第一项实施验证检查目标版本下引导资源、认证、媒体识别、控制栏入口和全屏容器；不使用先访问插件管理页才能“激活”的方式。DOM 或播放器契约不匹配时禁用该页弹幕集成并记录诊断，原播放器继续工作。
- M1 采用原生浏览器渲染层，不另建前端应用框架。模式 `1` 为从右到左滚动、`4` 为底部固定、`5` 为顶部固定；按视频时钟计算位置并在暂停、倍速及跳转后重算。建议滚动显示周期 8 秒、固定显示周期 4 秒，作为本轮全文审阅的默认值，不增加用户速度设置。
- 轨道根据有效视频画面和显示区域计算，弹幕不侵入控制栏交互；以纯文本或 Canvas 文本绘制，不解释 HTML。不得容纳的条目直接跳过，字号异常大时不扩大视频画布。全屏将弹幕层置于播放器全屏容器内，按设备像素比处理清晰度。
- 画中画不创建弹幕层；浏览器有可用进入/退出事件时仅暂停原页面弹幕渲染并在返回时定位当前进度，不做画中画专用支持。此项是退出不支持模式后的资源管理，不纳入画中画显示功能。

### 已确认的 Web 接入开关运行时效果

- 管理员关闭 Web 弹幕支持后，服务端立即停止为新加载请求提供弹幕；返回正常停用状态，客户端不将其显示为加载故障。
- 已经加载集合并正在播放的页面继续使用本次数据，不新增实时撤销轮询或推送。退出播放再开始、重新加载或刷新页面后不再展示弹幕入口；设置页明确提示“已打开的播放页刷新后完全生效”。
- 恢复启用后，新打开或刷新的页面可获得弹幕入口；不要求已经移除入口的页面自动重新接入。此规则仅针对弹幕显示，不影响 Jellyfin 自身播放或已存储数据。

### 已确认的有限播放数据加载方式

- M1 采用一次请求返回本次选定的有限弹幕集合，服务端完成分档、筛选并返回实际生效的显示密度配置；不发送全部导入数据。不按播放进度逐分钟补取，避免反复请求改变本次选定集合或总量。
- 首次弹幕加载与视频播放并行，不等待弹幕返回才开始视频；响应返回后从视频当前进度显示，不补播请求期间已错过的条目。
- 浏览器仅保留当前播放的选定集合。已成功加载后，管理员切换、替换或删除文件不会影响当前播放；数据库读取须取得一致的文件版本和配置快照。读取与删除竞争时须保证结果完整或返回明确失败，不返回半份数据。
- 暂停、继续、跳转和用户开关弹幕复用已加载集合。退出播放或切换视频时释放弹幕数据、事件监听及渲染资源；刷新页面或重新进入播放视为新播放，重新读取当前生效选择与配置。
- 初次加载失败后在播放页面按既定规则提示一次，并提供手动重试入口；重试成功或失败均在播放页面反馈，不要求用户进入设置面板查看。成功前不建立可渲染集合，不能通过重试将不同批次数据累加为本次播放集合。

### 已确认的播放请求与手动重试

- 每次进入视频播放生成新的不透明 `playbackId`，请求携带该标识及媒体 ID。服务端将其与认证用户、目标媒体绑定，不接受同一标识跨用户或跨媒体复用；所有请求仍需重新验证媒体权限。
- 同一播放首次成功创建选定集合时固定文件版本、加载配置与显示密度配置，首次响应丢失或网络失败后的手动重试复用同一集合，不重新抽样，不拼接多次响应。服务端在生成完整响应前保持数据库读取的一致性。
- 尚未建立选定集合即发生错误时，重试按当时的有效状态建立集合；已建立后则固定，管理员后续切换文件不改变它。若管理员停用 Web 支持或用户失去媒体权限，重试不得通过旧标识继续读取数据。
- 为初次加载重试保留服务端集合 10 分钟，从集合建立时开始计时，重试不延长；只保存已筛选的有限播放字段，不复制整个原始弹幕文件。浏览器加载成功后的播放、暂停、跳转及开关不依赖这份服务端重试缓存。
- 过期后返回明确的播放请求过期状态，不在同一 `playbackId` 下悄悄生成新集合。界面提示重新进入播放以开始新请求；重新进入视为新播放，沿用用户已确认的行为。
- 已确认的反馈位置：单次播放的加载失败、手动重试成功或失败均在播放页面反馈，采用不打断视频的短暂提示；不在设置面板展示单次播放状态。设置面板仅在涉及数据问题或配置合理性时提供相关说明。
- 自动失败提示在同一次播放内只出现一次；用户主动重试后，每次均反馈本次操作结果，不受自动提示次数限制。重试入口位于播放页面，执行期间禁用，防止并行重复请求；迟到响应不得覆盖已经切换到其他视频的播放状态。
- 缓存须有全局容量限制，容量不足时拒绝创建新集合并返回可重试状态，不淘汰尚处于承诺保留期的集合后静默重新抽样。容量预算与故障测试在实施计划中列明；服务重启后已有请求元信息仍可识别，无法恢复的集合返回 410，不生成替代集合。过期请求元信息保留到其登录会话失效或明确退出播放，避免清除后将旧标识当作新播放；此限制不影响浏览器已经加载的数据。

### 已确认的管理页面组织

Danmuku 管理入口位于 Jellyfin 管理后台，页面按以下四个功能区组织，均限管理员访问：

| 功能区 | 主要内容与操作 |
| --- | --- |
| 媒体绑定 | 搜索并选择影片或剧集单集，查看已绑定文件及当前生效文件；上传导入、绑定已有文件、切换生效、停用、替换或解除绑定；提供失效绑定筛选及全部绑定检查入口 |
| 弹幕文件 | 分页查看服务器留存文件名、格式、条目数、大小、导入时间及引用数量；搜索文件、筛选未绑定文件、查看引用媒体、下载原文件；无引用时可删除 |
| 导入任务 | 查看本批及近期任务的阶段、百分比和统计摘要；仅异常条目提供默认每页 50 条的分页列表；提供单文件及本批一键跳过异常、取消待确认文件导入等操作 |
| 设置 | Web 接入开关与状态、按时长分档的加载条数、低中高重叠四档同屏保护上限；说明保存后对新播放生效，用户显示偏好不在此统一覆盖 |

- 文件列表、媒体搜索结果及任务列表采用服务端分页，不一次加载全部数据；默认每页 50 条。异常条目分页沿用已确认规则。
- 删除文件和替换绑定前说明影响范围；正在被引用的文件不允许直接删除，提示先处理绑定。普通生效切换即时提交，不反复要求确认。
- 媒体搜索仅允许最终选择可播放的影片或单集；剧集与季作为导航层级，不将整季或整部剧集当作单个视频绑定。
- 本章确定信息组织和操作入口，具体布局与文案在实施计划审阅通过且用户明确授权后的前端实施中完成，并按已确认流程验证。

### 管理页面已确认要求

已确认的管理页面要求：异常条目处理提供单文件及本批待确认文件的一键跳过并导入正常条目入口，展示统计与原因，不要求逐条处理；具体规则见第四章。

## 7. 验收标准

### 自动化验证

- 两种真实样本格式均可导入，核对实际条目数、时间精度、文本、模式、颜色、字号和源 ID；新增样本中缺少 `progress` 的条目须按既定规则报告。真实样本通过执行环境提供的路径只读加载，以哈希识别，不提交仓库；CI 使用结构对应的人工构造数据。

- 验证 30/60 分钟分档边界、未知时长回退、配置生效时机、稳定抽样、总量不超限、暂停/跳转/开关不重新加载，及失败提示不阻塞视频。
- 验证 Web 入口重复部署不重复插入、日常禁用仅关闭功能、撤销与卸载只清理本插件标记、升级入口重新生成；容器重建后配置和弹幕数据仍在。
- 执行两插件相关 build/test/package 及独立加载、共存 smoke 检查，确保 Danmuku 变更不破坏 AgentBridge。自动化失败先修复并回归，不进入人工测试。

### 审阅修订对应的验收补充

以下补入现有替换隔离、批次顺序与重启恢复测试，不扩大产品范围；尚未执行：

- 替换：A 被多个媒体共享；替换生效/非生效 A；媒体已停用；B 是新内容、已存在文件、当前媒体已绑定文件以及 B=A。检查旧文件本体和其他媒体引用保留，去重优先，只有完整提交才报告替换完成。

- 上传位置：批次创建后直接关闭页面；第二个文件上传中断；前序上传失败而后序已接收；取消无任务 ID 的位置；等待接收及请求期限到期；接收完成但响应丢失。检查已接收任务不因页面关闭被取消，失败位置释放发布顺序，批次最终能够结束，重复请求不生成第二个任务。
- 中断与保留：重启后中断任务及未接收位置不再运行，记录终态时间；满 7 天清理摘要/异常明细，重复重启不延长保留。确认终态清理不删除正式文件和绑定。
- 删除术语：解除生效绑定必须同时选择另一文件或停用；解除非生效绑定不改变生效选择；有引用的文件本体仍禁止删除。

## 8. 四档动态密度修订（整体审阅已通过）

本章只影响 Danmuku 播放密度、相关管理员配置及验证基线；AgentBridge、导入格式、媒体绑定、服务端一次加载上限和固定选定集合规则不变。没有开始本章的功能实现。本章规则及细则已获整体审阅通过，不把已批准算法或性能目标写成测试结果。

### 8.1 已逐项确认的产品规则

| 档位 | 预计占用预算 | 默认同屏保护上限 | 碰撞规则 |
| --- | --- | --- | --- |
| 低 | 所选弹幕区域面积的 40% | 100 条 | 所有普通弹幕防重叠及追尾 |
| 中 | 所选弹幕区域面积的 65% | 200 条 | 所有普通弹幕防重叠及追尾 |
| 高（默认） | 不另限占用比例 | 400 条 | 尽量容纳能安全排布的条目 |
| 重叠 | 不另限占用比例 | 600 条 | 滚动可互相重叠，也可覆盖固定弹幕；固定弹幕彼此不重叠 |

- 界面名称固定为“低、中、高、重叠”，默认高；占用预算和保护上限是不同限制，不把保护条数当作目标显示条数。
- 画面占用口径为“预计文字面积 ÷ 所选显示区域面积”。文字面积使用包围盒估算，考虑文本长度、字号、描边及必要行高；在进入前预估，不仅计算刚入屏时露出的部分。
- 密度档位不改变上下间距，行高随字号适应；低／中／高不再对应三种横向间距。前三档保持独立防碰撞。
- 四档保护上限由管理员分别配置，计数为滚动、顶部、底部弹幕合计。达到限制时跳过新条目，不延后补播；不修改源条目或其时间。
- 显示区域为实际视频画面顶部向下的 25%／50%／75%／100%，默认 75%，不含黑边。底部固定弹幕贴所选区域下边缘。密度变更不接管字幕，不新增自动避让字幕能力。
- 当前处于开发阶段，不实施用户偏好迁移，撤销此前的一次性迁移要求。必须保留现有测试环境已导入文件、标准化弹幕、媒体绑定及当前选用关系；不以“无需迁移”为理由清空或重建业务数据。
- 40%／65% 和 100／200／400／600 已获确认，但新算法画面效果及高负载性能尚未验证。

### 8.2 占用计算与释放（已通过）

采用完整生命周期内的预计占用预留，以稳定预算代替逐帧可见像素统计。

**坐标与分母。** 使用实际视频画面的 CSS 像素宽 `W`、高 `H`，显示区域比例 `r`，可用高度 `Ha = H × r`，分母 `A = W × Ha`。设备像素比只影响 Canvas 清晰度，不放大占用预算。尺寸为零或未知时不接纳新条目，几何恢复后重新计算。

**单条面积。** 按原始字号乘用户字号缩放测量文本。记包含描边后的完整文本宽为 `w`，包含字形高度、描边和统一行高要求的占用高为 `h`，单条预计占用 `a = min(w, W) × h`。行高取足以容纳实际字形及描边的统一规则，不随密度档位改变；测量的跨浏览器回退方式在实施计划中展开。包围盒包含字间空白，不逐像素统计墨迹，不因颜色或不透明度降低其权重。

**长文本与大字号。** 超宽文本的计费宽度最多为画面宽，避免屏外文字无限增加预算；实际运动和碰撞仍使用完整文本宽，不截短文字或自动缩小字号。高度超过所选区域的条目跳过。单条预计面积超过低／中档预算时也跳过，不强制放行或扩大预算；这是长文本、大字号在低密度下可能不显示的明确结果，需用样本人工检查可接受性。

**准入与释放。** 对已接纳且尚未结束的条目累计 `S = Σa`，滚动和固定共用预算。低／中档仅在 `S + a ≤ 0.40A / 0.65A` 时允许继续尝试排布；高和重叠档跳过此项比例检查，仍检查数量和碰撞规则。只有成功排布的条目才计入面积和条数，失败不占名额、不撤下旧条目。预算在成功接纳时全额预留，到该条目结束时释放，部分进入或部分离屏不提前释放；暂停不释放。关闭、退出及重新构建画面时清空旧账本。

这是一种保守的预计占用比例，不是文字实际遮住的视频像素比例。示例：视频画面 1280×720、区域 75%，`A=691200`；若每条预计面积为 320×32，则低档面积预算能接纳至多 27 条，中档至多 43 条。实际值还可能因碰撞、时间分布及保护上限降低，不能将示例条数写死为档位配置。

### 8.3 排布、突发与重建（已通过）

- 沿用现有滚动和固定弹幕的显示时长、视频时间同步和字号缩放；不以提速、缩字或改变时间戳来提高密度。服务端选定集合不因换档、全屏、尺寸变化或拖动进度重新抽样。
- 前三档同时检查当前相交与剩余运动期间的追尾；不仅在入口留一段空白。同一密度档不改变行高或人为拉大行间距，固定的防碰撞留白对所有档位采用同一规则。
- 重叠档只在固定弹幕之间保持防重叠，包括顶部与底部固定条目的相互检查。滚动不阻止新固定条目接纳，固定也不阻止新滚动条目，允许二者相互覆盖；所有文字依然限制在所选区域。
- 重叠档先尝试无碰撞位置，空间不足时再复用轨道；复用位置采用稳定顺序并分散到可用轨道，避免总压在第一行，不随机抖动。精确选择规则由实施计划细化。
- 同一时间先释放已结束条目，再按出现时间及集合中的稳定源顺序尝试新条目。低／中依次检查数量、面积、排布；高／重叠检查数量和各自排布规则。失败即跳过，不等待、不驱逐已显示弹幕，也不另作语义评分或按长短排序。
- 同样的集合、设置、画面尺寸和配置快照，应得到同样的准入和位置。连续播放、暂停恢复及拖动到同一时刻应一致，不能仅随意重放最近几秒而忽略此前预算和碰撞造成的拒绝结果。可采用按事件重演或有界检查点实现，具体算法与内存预算放入实施计划。
- 用户修改密度、区域或字号，以及画面尺寸改变时，按新条件重建当前画面；不沿用可能超额的旧布局。关闭后重新开启同样从当前时间恢复，不补播关闭期间的历史条目。重建不得长期阻塞播放器主线程，响应时间仍受第七章约束。

### 8.4 管理员配置与开发期兼容（已通过）

四档同屏保护上限都允许配置为 **1–600 的整数**，要求 `低 ≤ 中 ≤ 高 ≤ 重叠`，默认 **100／200／400／600**。600 作为本轮拟验证的最高支持范围，不开放零、无限制或大于 600 的值。未来提高范围需要另行验证，不能外推本轮性能。非整数、越界、缺项或顺序非法的保存请求在页面与服务端都拒绝，保存失败不改原配置；恢复默认同时恢复四个值。

40%／65% 是固定的产品档位参数，本轮不再增加管理员占用比例配置。页面清楚区分“按时长加载条数”和“四档同屏保护上限”，说明实际显示还受占用预算与碰撞制约。修改保护上限只影响新开始的播放，当前播放及重试继续使用创建选定集合时固定的配置快照。

开发期配置处理规则：

- 新的四档保护字段不复用旧三档条数字段；旧三档值不自动换算成新值。读取缺少新字段的旧配置时采用新默认值，保留 Web 开关、加载上限等无关配置；首次成功保存新配置后以新字段为准。字段名和响应结构在实施计划中定义。

- 服务端播放响应提供本次四档保护配置，浏览器静态资源与响应契约配套更新，沿用已有资源版本机制避免旧缓存误用。旧资源或异常响应无法解释新契约时应按弹幕失败路径处理，不使原生视频或字幕停止；兼容分支及契约测试由计划明确。
- 不修改数据库业务模型、不重导入弹幕、不清空绑定或生效选择。后续部署前保留可恢复的配置／数据备份，并核对部署前后文件内容哈希、标准化条数、绑定与生效选择一致。测试生成数据仅放隔离实例，不覆盖人工测试数据。

### 9.3 独立文件导入

现有创建导入批次接口要求媒体 ID，并在发布时检查媒体版本及完成绑定。本修订增加明确的“仅导入文件”意图，与“追加并绑定”“替换绑定”区分，不能通过虚构媒体 ID 或先绑定再解绑实现。

- 从弹幕文件区选择最多 10 个文件创建独立批次；不要求先选择媒体，不携带或继承媒体区的选中状态。
- 沿用现有格式、大小／条数限制、上传位置、解析、异常确认、取消、超时、恢复和任务保留规则。成功后文件可在文件列表检索，正常新文件引用数为 0；不创建媒体绑定、不改变任何媒体生效状态或版本。
- 沿用原内容哈希去重规则：重复内容复用已有文件，不制造重复本体，也不解除已有文件的引用。结果说明复用情况；因此复用的已有文件可能已被其他媒体引用。
- 独立批次不参与媒体版本冲突检查，不展示“刷新绑定并决定继续”；仍受文件发布、容量、权限及取消规则约束。原追加／替换流程的媒体权限、版本检查和事务语义不变。
- 任务表明确显示“仅导入文件”“追加并绑定”或“替换绑定”，避免将独立导入成功误解为可立即在某个视频中播放。
- 管理员之后如需使用该文件，在媒体绑定区选中媒体，再选择已有文件完成绑定；绑定与生效行为沿用原规则。
