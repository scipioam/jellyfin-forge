## 1. 目标与范围（已确认）

M2 仅涉及 Danmuku 插件，在 M1 基础上增加弹幕速度设置、多文件合并与时间轴对齐，并在保持依赖轻量的前提下优化管理员页面。保持两插件独立，不扩展 AgentBridge 的职责。

### 1.1 弹幕速度

- 播放面板增加速度设置，控制弹幕在屏幕上移动的快慢。
- 弹幕出现时间仍与视频时间轴同步；本项设置不用于修改弹幕的出现时间。
- 与视频倍速、固定弹幕停留时间的关系，以及设置范围、默认值和偏好保存方式，见第二章已确认规则。

### 1.2 管理页面

- 在轻量依赖约束下优化布局、视觉层级和操作反馈，并融入多文件合并操作。
- 不引入第三方 UI 库；使用现有控件能力、局部 CSS 和原生 JavaScript，具体交互及视觉规则见第五章。

### 1.3 多文件合并与时间轴对齐

- 支持为一个视频选取多个弹幕文件进行合并。
- 每个文件可独立设置取值时间范围，并将选取范围映射到视频的指定起点。
- 例如：B 文件取源时间 `10:00–20:00`，从视频 `20:00` 开始使用该片段；具体边界和映射规则见第三章。
- 提供一键同步所有文件取值范围的快捷功能；同步仅覆盖源范围，保留各行视频起点，具体规则见第三章。
- 合并结果以视频所属的合并方案保存，生效关系、修改与删除规则见第四章。

### 1.4 兼容与验收

- 保留 M1 文件、绑定和用户设置，明确升级后的行为。
- 明确容量限制、异常处理、自动化验收和人工体验检查。
- 历史设计中留给 M2 的扩展，以本次逐章确认的范围为准，不自动将其他时间轴编辑能力纳入。

## 2. 弹幕速度设置（已确认）

- 在现有播放器弹幕设置面板增加“滚动速度”滑块，范围 `0.5×–2.0×`，步长 `0.1×`，显示当前数值。
- 默认 `1.0×`，保持 M1 滚动弹幕横穿画面用时 8 秒的速度；`2.0×` 用时减半，`0.5×` 用时加倍。速度设置不改变弹幕出现时间。
- 顶部／底部固定弹幕继续显示 4 秒，不受滚动速度设置影响。
- 延续以视频时间为基准的行为，上述用时均为视频时间。视频倍速影响现实时间中的移动速度及固定弹幕停留时间；例如视频 `2×`、滚动速度 `1×` 时，滚动弹幕横穿画面的现实用时为 4 秒。
- 调整后立即按当前播放进度重新排布，无需重新开始播放；当前可见弹幕位置可能变化。
- 沿用现有弹幕偏好的保存方式，切换视频后保留；旧用户没有该设置时使用 `1.0×`。
- 保留现有密度与防碰撞规则。速度降低后占屏时间增加，可能使后续弹幕更容易被跳过；不因此自动提高密度或延迟补播。

## 3. 多文件合并与时间范围（已确认）

### 3.1 来源片段与时间映射

- 每行代表一个来源片段，包含来源文件、源开始、源结束、视频起点，并展示对应视频区间。
- 同一文件允许添加多行，用于截取不同片段并分别对齐；不同片段映射到相同视频区间时叠加。
- 时间映射采用等速平移：`视频出现时间 = 源弹幕时间 − 源开始 + 视频起点`，不拉伸或压缩时间。
- 例如：A 取 `10:00–20:00`、视频起点 `00:00`，映射为 `00:00–10:00`；B 取 `10:00–20:00`、视频起点 `20:00`，映射为 `20:00–30:00`；C 取 `00:00–10:00`、视频起点 `20:00`，与 B 在该视频区间叠加。

### 3.2 范围与默认值

- 源范围包含开始、不包含结束，例如 `[10:00, 20:00)`，避免相邻片段重复取到边界弹幕。
- 默认源开始为 `00:00`、源结束为“到文件末尾”、视频起点为 `00:00`，即默认使用完整文件。“到文件末尾”包含最后一条源弹幕，不将其出现时间作为排除式结束边界或视频时长。
- 源开始和视频起点不能为负；指定源结束时必须晚于源开始。时间支持毫秒精度。
- 修改源开始时，视频起点保持原值，二者独立设置。

### 3.3 一键同步范围

- 每行提供“将此范围应用到全部”，将该行的源开始、源结束复制到当前所有其他行，不覆盖各行视频起点。
- 同步属于一次性复制，复制后仍可逐行修改；后来添加的行使用默认值。
- 支持撤销本次批量覆盖，恢复被覆盖的范围；具体交互见第五章。

### 3.4 重复与排序

- 保留不同来源中的重复弹幕，不进行自动文本去重；用户已明确认可不自动去重。
- 完全相同的“文件＋源范围＋视频起点”重复行阻止保存，并提示删除重复配置。
- 合并后按视频出现时间排序；同一时间按配置行顺序、源条目顺序稳定排列。

### 3.5 保存前反馈

- 展示每行选中条数、映射后区间及合计条数。
- 某行没有选中弹幕时提示，但允许保留；全部结果为空时阻止保存。
- 已知视频时长时，提示落在视频结束之后的弹幕数量，允许保存；播放时这些条目不参与加载额度和抽样。

## 4. 合并结果与数据生命周期（已确认，含复审补充）

### 4.1 保存与生效

- 合并配置保存为视频下的“合并方案”，具有名称，记录来源文件、取值范围、视频起点及行顺序；原始文件保持完整。
- 新建方案默认自动命名为 `combine-1`、`combine-2` 等，支持手动编辑修改；名称限制及冲突处理见第六章。
- 一个视频可保存多个方案；同一时间只能选择一个已绑定单文件或一个所属合并方案生效，也可以停用弹幕。
- 提供“保存”和“保存并启用”。仅保存不改变当前生效选择。
- 所有修改生效选择的操作继承媒体级预期版本保护，方案内容另受方案版本保护，具体见 6.3（本轮 R2 补充，已复审通过）。已有生效方案时，首次追加单文件也保留方案选择，不因没有单文件绑定而自动启用新文件。
- 方案可修改名称、来源片段、时间范围、视频起点和行顺序；保存失败保留原方案。
- 生效方案修改保存后供下次开始播放使用；当前播放继续使用开始时的版本。切换生效项及删除操作也不得破坏当前播放的既定版本。

### 4.2 来源文件与引用

- 从已有文件库选择来源；未导入的文件沿用现有导入流程，成功后再加入方案。
- 加入方案即可建立来源引用，不要求先将每个来源文件单独绑定到视频。
- 文件被任一方案引用时禁止删除，即使方案未生效；管理页面展示引用位置。
- 单文件绑定与方案引用独立。解除单文件绑定不将文件从方案中移除；原有“替换文件”操作不自动替换方案来源。方案来源须在方案内明确修改。

### 4.3 删除与兼容

- 删除非生效方案不影响当前生效选择；删除生效方案时，须选择其他已绑定单文件／所属方案，或明确停用。
- 删除方案只解除来源引用，不自动删除来源文件。
- M1 单文件绑定与生效选择原样保留，不要求转换成合并方案。
- M2 支持在所属视频内管理方案，不纳入跨视频共享方案及导出合并文件。
- 本轮 R1 补充（已复审通过）：媒体失效检查覆盖有单文件绑定或合并方案的媒体，包括只有方案、没有单文件绑定的媒体。媒体确定不存在时保留方案及来源文件，允许管理员从失效记录进入方案列表，显式删除方案解除引用，不按名称或路径自动迁移，也不自动清理。
- 失效媒体上仍为生效项的方案只能在明确停用的同时删除，删除、解除引用与停用一起成功或失败；非生效方案可显式删除。媒体失效不阻止上述清理，但继续禁止新增方案、编辑保存或启用。文件只在全部引用解除后才可另行删除，其他媒体或方案的引用不受影响。
- 媒体查询失败标记为检查失败，不等同于媒体确定不存在，不触发自动清理或迁移。

## 5. 管理员页面交互与视觉（已确认，含复审补充）

### 5.1 页面结构

- 保留“媒体绑定、弹幕文件、导入任务、设置”四个分区，在 Jellyfin 管理页内统一样式。
- 媒体绑定：选择视频后，顶部显示视频名称、时长和当前生效项，下方分为“单文件绑定”和“合并方案”。生效状态显示为“单文件：名称”“合并方案：名称”或“已停用”，提示变更在下次播放生效。
- 弹幕文件：保留搜索、分页和独立导入，引用详情同时展示单文件绑定和方案引用。
- 导入任务：用状态文字、颜色和进度区分处理中、待确认、成功及失败。
- 设置：保留加载上限与同屏保护上限分组，统一表格、输入框和说明样式。
- 本轮 R1 补充（已复审通过）：复用媒体绑定分区的全量检查及失效列表入口，覆盖仅有方案的媒体；即使视频已无法通过媒体搜索选中，管理员仍能从失效记录进入其方案列表并按 4.3 清理引用。列表区分媒体不存在与检查失败，不新增顶层页面。

### 5.2 合并方案编辑

- 在当前视频详情内展开编辑区。顶部预填自动生成的方案名称并允许编辑，使用带搜索和分页的文件选择器添加来源。
- 每行展示文件名、源开始、源结束、视频起点、映射后区间和选中条数。
- 提供“上移／下移”“移除”“将此范围应用到全部”，通过按钮调整顺序，支持键盘操作。
- 底部展示总条数、空片段及超出视频时长提示，提供“保存”“保存并启用”“取消”。
- 统计未完成时显示“计算中”，失败时提供重试入口，不将旧统计作为当前结果；最终保存由服务端重新校验。

### 5.3 范围同步与未保存保护

- 执行范围同步后显示覆盖的行数，并提供“撤销”。
- 撤销保留到下一次片段编辑、增删、排序或再次同步之前，避免覆盖后续修改。
- 有未保存修改时，切换媒体、关闭编辑或离开分区，提示放弃修改或继续编辑。
- 保存失败保留当前输入，在对应字段或编辑区显示原因。

### 5.4 视觉、控件与依赖

- 使用 Jellyfin 现有控件能力、插件局部 CSS 和原生 JavaScript；不新增前端框架、第三方 UI 库、远程字体或 CDN 依赖。
- 用户明确允许适当美化页面，包括 checkbox 等控件样式。统一复选框、开关、输入框、按钮、表格的视觉和间距，保留清楚的选中、禁用、悬停及键盘焦点状态，不因美化改变控件语义或操作方式。
- 主操作突出，删除等危险操作放在次要位置；颜色跟随 Jellyfin 主题，状态同时带文字，不只依靠颜色区分。
- 样式限定在插件页面内，避免影响 Jellyfin 其他页面。
- 桌面优先保证时间表格可读；窄屏允许表格局部横向滚动，避免整页溢出。控件保留可见标签、键盘操作和焦点提示。

## 6. 兼容、限制与异常处理（已确认，含复审补充）

### 6.1 升级与播放兼容

- 升级保留现有文件、单文件绑定、生效选择和播放器偏好；无滚动速度偏好时默认 `1.0×`。
- 数据库迁移前备份，失败时保留原数据，不以空库替代。
- 合并播放沿用 M1 的加载数量、密度和同屏保护限制。先完成范围筛选和时间映射，排除已知视频时长之外的条目，再对整个合并结果统一抽样；不为每个来源分别分配一份加载额度。
- 当前播放固定使用开始时的方案版本和选定弹幕集合，不受管理员后续修改影响。

### 6.2 规模与名称限制

以下为固定上限，M2 不增加对应管理员配置项；超限明确提示，不静默截断。

| 项目 | 上限或规则 |
| --- | --- |
| 每个视频保存的合并方案 | 20 个 |
| 每个方案的来源片段行数 | 50 行，同一文件的多行分别计数 |
| 每个方案选中的弹幕总数 | 100 万条，重复条目及超出视频时长的条目也计数 |
| 方案名称 | 去除首尾空白后 1–100 个 Unicode 码点，同一视频内不重名 |

- 新建方案默认使用 `combine-1`、`combine-2` 等自动名称，支持手动编辑修改；自动命名须遵守同一视频内不重名规则。编号分配和并发冲突处理的实现细节留给实施计划，不将自动命名视为免除保存校验。
- 100 万条限制约束服务端处理规模，不代表浏览器加载数量；实际播放仍遵守 M1 加载额度。
- 原文件导入限制保持不变。

### 6.3 保存与并发

- 方案内容、来源引用及“保存并启用”的生效切换一次成功或一起失败。
- 两个页面同时修改同一方案，后提交者遇到版本冲突时保留输入，提示重新加载核对，不静默覆盖。
- 本轮 R2 补充（已复审通过）：凡修改媒体生效选择的操作，均沿用媒体级预期版本校验，包括单文件／方案切换、停用、保存并启用，以及删除生效方案时选择替代项或停用；方案内容更新另受方案版本保护，不能只检查各自方案版本。
- 版本检查与相应写入在同一事务中完成；冲突时保留输入，提示重新加载核对，本次操作不得改变任何已保存内容、引用或生效项，不允许部分提交。
- 原追加／替换导入须识别方案操作引起的媒体状态变化，按既有媒体版本冲突与显式恢复流程处理，不恢复旧选择。仅保存方案始终不改变生效选择，也不恢复编辑开始时的选择。
- 来源文件已删除、媒体已失效或参数不合法时，拒绝新增／编辑保存并指出原因。媒体失效时禁止启用，但不阻止 4.3 的显式删除、解除引用及停用清理；清理同样遵守版本校验和原子提交要求（本轮 R1 补充，已复审通过）。
- 文件删除与方案保存同时发生时，不得留下指向已删除文件的方案。

### 6.4 失败与边界情况

- 生效方案缺少来源数据时明确报告加载失败，不悄悄播放剩余来源；视频正常播放。
- 视频时长未知时允许保存和播放，提示无法检查超出时长的条目；不把最后一条弹幕时间当作视频时长。
- 源选取结果非空、但映射后全部落在已知视频时长之外时，允许保存并警示；播放返回空弹幕结果，不算加载失败。
- 统计请求或媒体切换后的迟到响应不覆盖当前编辑内容。
- 方案管理仅管理员可操作；播放继续校验用户对目标视频的访问权限。

## 7. 验收标准（已确认，含复审补充）

本章规定后续验收要求，不表示检查已经执行或通过。测试矩阵、样本、测量步骤及人工操作步骤在对应实施计划中展开。

### 7.1 功能与回归覆盖

| 验收项 | 主要检查 |
| --- | --- |
| 滚动速度 | 默认值、调整范围、即时生效和偏好保存；固定弹幕不受速度设置影响；视频倍速、暂停、跳转及四档密度下行为正确 |
| 时间范围与对齐 | 毫秒精度、开始包含／结束排除、到文件末尾、多片段叠加；验证源范围从 `10:00` 开始、视频起点为 `20:00` 时，源 `12:00` 映射至视频 `22:00` 等明确样例 |
| 同步与重复 | 同步只覆盖源范围、保留视频起点；撤销行为正确；不同来源重复弹幕保留，完全重复配置行被拒绝 |
| 方案管理 | 自动命名、手动改名、保存与启用、切换和删除；来源引用保护；当前播放不受后续编辑影响 |
| 限制与异常 | 三项规模上限及超限；空结果、时长未知、来源缺失、并发冲突、保存失败和迟到响应 |
| 管理页面 | 四分区完整可用；控件样式、主题适配、键盘操作、窄屏布局、未保存保护和统计反馈 |
| 升级与回归 | M1 文件、绑定和偏好保留；原导入、替换、播放和权限行为正常；两插件独立加载及共存 |

本轮审阅补充的验收场景（已复审通过，尚未执行）：

- R1：为无单文件绑定的视频建立方案后模拟媒体确定不存在；全量检查及失效列表应覆盖该媒体，并可进入方案列表。原方案和来源文件保留，直接删除被引用文件仍被拒绝；显式删除方案解除引用，生效方案同时明确停用，其他引用不受影响，文件本体保留。另验证查询失败不会误判为媒体不存在或触发自动清理／迁移，失效媒体不能新增、编辑保存或启用方案。
- R2：两页分别编辑 P、Q，Q 先保存并启用后，旧媒体版本的 P 保存并启用应冲突，P 的内容和引用也不得部分提交；一页准备删除生效方案并停用，另一页先切换到单文件，旧删除请求不得撤销新选择。
- R2：追加／替换任务校验期间切换到方案，发布应按媒体版本冲突规则处理，显式恢复后按最新状态继续；已有生效方案时首次追加单文件不得自动取代该方案。另一页改变生效选择后，仅保存非生效方案不得恢复旧选择，同一方案的内容竞争仍拒绝静默覆盖。

### 7.2 性能验收

- M2 重新验证性能，覆盖低速导致占屏时间增加，以及 50 行、100 万条候选的合并场景，不以 M1 历史成绩替代本轮结果。
- 沿用 [M1 设计](M1-Danmuku-Design.md)第七章及第八章的相关性能目标：加载就绪热运行 20 次 P95 ≤2 秒；设置及 seek 响应各 20 次 P95 ≤200 毫秒；连续 10 分钟视频掉帧增量 ≤1 个百分点。首次冷启动单独记录。
- 具体矩阵和测量步骤在实施计划中确定，覆盖默认及约定的最大配置、速度调整、长视频后段重建和大幅向后跳转；不能用默认配置结果代表最大配置结果。

### 7.3 验证顺序与人工体验

- 相关自动化测试、必要构建、打包及 smoke 通过后，进入人工测试。人工发现问题后，先修复并通过相关自动化回归，再人工复测。
- 人工单独确认速度是否舒适、合并对齐是否准确、管理页面及 checkbox 等控件是否清晰易用；自动化通过不等于人工验收完成。
- 正式浏览器范围沿用桌面 Chrome、Edge、Firefox；窄屏布局检查不等于新增移动端支持。
- 如实记录实际版本、执行结果和覆盖限制；未执行、失败或受阻的检查不标记通过。
