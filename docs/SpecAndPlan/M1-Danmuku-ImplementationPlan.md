## 4. 实施顺序与完成条件

所有阶段当前均为“未执行”。P1 是第一项实施工作，只有明确开工授权后才进行最小接入代码及容器实验。后续按 P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 → P10 推进；各阶段随实现补充对应自动化验证，P9 汇总完整结果。

### P1：验证目标版本 Web 接入

1. 在隔离实例验证固定同源引导、Base URL 根路径及非空路径、公开启用状态、静态资源类型和插件禁用后的安静退出。
2. 实现最小 Web 适配，证明可以取得当前媒体 ID、实际视频元素、播放进度、认证上下文和控制栏/全屏容器；验证直接打开播放页面，无需先进入管理页。
3. 以少量人工构造弹幕验证开关、页面切换、全屏、暂停与跳转；不接入真实业务存储。验证浏览器中的实际播放，不以静态 DOM 插入成功代替。
4. 将通过的接入代码收敛为正式适配模块，去除临时调试入口。保存兼容性验证结果于 `artifacts/m1/web-integration/`。

**完成条件：** Chromium 和 Firefox 自动化均能独立进入播放页并使用最小叠加层，原播放器及登录流程不受影响，入口可撤销。若目标版本契约无法满足已批准设计，停止后续依赖工作并修订设计，不绕过为浏览器扩展、其他插件依赖或 Web fork。

### P2：建立持久化、依赖与发布基础

1. 加入固定 SQLite 依赖和 Danmuku 专用服务注册，沿用现有 .NET 工程约束。
2. 建立设计中的文件、弹幕、媒体状态/绑定、批次/位置/任务/异常、播放请求和结构版本表；用事务及约束实现生效引用完整性，配置主键与分页/时间索引。
3. 实现数据目录解析、首次建库、迁移前一致性备份和失败保留；不通过空库覆盖旧数据恢复。
4. 实现发布意图登记、暂存转正式、提交前后的恢复，以及删除标记与磁盘清理重试；故障注入覆盖各持久化边界。
5. 提前修改 `build/package.py` 的 Danmuku 分支，生成依赖清单，验证 ZIP 能在干净实例创建数据库及读写，不借用构建输出目录或 SDK 缓存。

P2 故障注入按持久化事务结果判定恢复，不能统一要求回到旧生效文件：

| 故障点 | 重启后预期 |
| --- | --- |
| 原文件已暂存或移动，但发布事务未提交 | 原绑定及生效选择不变，任务标记中断；仅清理能够确认属于未完成任务的数据 |
| 发布事务已提交，但成功响应尚未返回 | 保留提交后的文件、条目、绑定及生效选择，任务恢复完成；不清理已发布文件，不重复发布 |
| 进程在提交边界退出，调用方无法判断结果 | 核对持久化事务结果，归入未提交或已提交状态；不出现半份绑定，不以成功响应是否送达决定回滚 |

**完成条件：** SQLite 测试、进程中断恢复与最小插件包加载通过；AgentBridge 包内容与独立性保持不变。

### P3：实现两种格式与异常统计

1. 使用流式 XML 和 JSON 读取，原文件同时写入任务暂存并计算哈希；不使用整文件 DOM 或把 30 万条装入单个集合。
2. 按设计实现秒转毫秒、源 ID 字符串优先、缺失字段默认值及告警统计、模式 1/4/5、100 码点判断、纯文本、附加来源信息和未知字段兼容。
3. 源顺序持久化，按时间和源顺序稳定排序；超出视频时长仍保存，不自动删重复弹幕。
4. 单条异常写入分页明细；正常条目不生成管理明细。整体结构失败、文件/源条目超限、零有效条目按设计拒绝，部分异常等待确认。
5. 创建不含真实用户文本的人工 fixtures 和边界数据生成器；外部样本通过 `DANMUKU_SAMPLE_DIR` 提供，依据设计哈希核对，不提交原样本或固定绝对路径。

**完成条件：** 两种人工样本和边界测试通过；外部真实样本分别完成统计与关键字段核对，结果与设计记录对照，不把两种格式当成完全相同的数据。

### P4：实现导入任务、绑定与替换

1. 创建批次即登记全部位置，实现 PendingUpload/Receiving/Accepted 和终结状态；绑定任务 ID 与位置唯一，重复请求返回已有状态。
2. 实现按列表发布、继续接收后序上传、一键确认单文件/本批异常、取消指定位置和未接收位置、期限收尾及终态 7 天清理。
3. 实现普通首次/追加导入、内容复用、同名后缀和主动停用状态保留。
4. `operation=replace` 持久化 `replaceFileId`，按批准的生效状态表原子提交；B 已存在或 B=A 时优先复用，不误报追加成功为替换完成。
5. 媒体绑定使用版本条件更新；冲突保留暂存，刷新后的 Resume 不丢失替换意图；A 已解除时拒绝继续原替换。
6. 实现失效绑定检查、单个检查和管理员全量检查任务。查询失败与媒体不存在分别处理；不会自动按同名或路径重新绑定。

**完成条件：** 复审提出的替换、空缺上传位置、中断保留场景全部有自动化覆盖；并发、取消、断连、响应丢失与重启均不会产生半份绑定或永久进行中的批次。

### P5：完成管理 API 与权限

1. 实现设计第五章列出的全部管理接口及 DTO；使用管理员认证，下载和引用查询同样受保护，固定公开资源仅采用白名单。
2. 分页默认 50、最多 100；按批次查询同时返回最多 10 个位置摘要，保持任务明细分页，不隐藏尚无任务的位置。
3. 返回阶段百分比、摘要、业务错误码和到期时间；不会把文件读完或数据库尚未提交显示成导入成功。
4. 配置读取/保存沿用 Jellyfin 插件接口，在服务端统一校验上下限与非递减关系，失败不改变旧配置；只对当前用户返回允许的数据。
5. 扩展隔离 HTTP 验证，覆盖管理员、普通用户、受限媒体用户和匿名请求；不能以属性反射测试代替实际授权行为。

**完成条件：** 管理流程可以完全由 HTTP 调用走通，错误与状态契约符合设计，既有 health 与配置兼容性通过。

### P6：实现受限播放集合及重试

1. 服务端读取媒体时长和权限，以配置快照确定加载档位；未知时长取最小档，不接受客户端自报时长作为授权依据。
2. 实现第五节规定的确定性筛选，最多返回配置条数；不传发送者哈希、源路径或完整导入集合。
3. 实现 `playbackId` 与用户、认证会话、媒体绑定，合并同一请求的并发创建；首次建成集合后固定文件版本和配置。
4. 保留有限集合 10 分钟供失败重试；成功播放不依赖缓存存续。到期返回 410，容量不足返回 503，权限撤销与 Web 停用优先于缓存命中。
5. 持久化请求元信息，重启无法恢复的集合明确过期；未失效会话的过期请求标识不被当作新请求重新抽样。

**完成条件：** 分档边界、稳定性、余数分配、重复请求、缓存容量、授权撤销及文件删除竞争测试通过；返回总量及会话隔离可由实际 HTTP 验证。

### P7：完成管理页面与播放器

1. 按四个功能区完成媒体绑定、文件、任务和设置页面，沿用 Jellyfin 管理页与原生 JS/CSS。提供阶段百分比与摘要，只有异常有分页明细，一键跳过不受当前页影响。
2. 显示替换/解除绑定/删除本体的不同影响，只有完整替换提交后显示成功；冲突恢复展示当前状态。
3. 以 Canvas 绘制有限集合，默认滚动周期 8 秒、固定周期 4 秒；用视频时钟计算位置、轨道和可见区，不用墙钟累积播放时间。
4. 实现默认及管理员三档密度、25%/50%/75%/100% 区域、10%–100% 不透明度和 50%–200% 字号缩放；按服务器和用户隔离本地偏好。
5. 无弹幕不提示；加载失败自动提示一次；播放页面提供手动重试并逐次反馈结果，不把单次播放消息放入设置面板。
6. 关闭、跳转、切换视频、退出登录和尺寸变化正确清理或重建；同屏已满直接跳过，不延迟补播，不因跳转增加选定集合。
7. 不为画中画添加渲染功能，仅在可用事件下暂停原页面资源，退出后定位当前进度。

**完成条件：** Chromium/Firefox 浏览器自动化验证全部页面和播放行为，无重复监听、迟到响应覆盖或正常条目全量列表；开始性能测试前具备资源释放测量点。

### P8：完成部署工具、升级及发布

1. 拟新增 `build/web-entry.py`，提供 prepare/verify/remove 操作，显式接收镜像、目标输出目录、Web 路径、Base URL；只生成产物，不默认操作远程服务。正式主机由操作者按说明应用挂载。

**完成条件：** 非 root、根/非空 Base URL、重新部署、升级入口、禁用、卸载路径均有自动化验证；文档无开发主机绝对路径、固定目标账号或正在运行的实例状态。

| --- | --- |
| 未开始上传位置的期限 | 批次创建后 60 分钟；到期记 Expired |
| 单文件接收期限 | 接收开始后 30 分钟，且连续无进展 120 秒即失败；不续传 |
| 接收/解析/发布并发 | 全局接收最多 2 个、解析 1 个、发布写入 1 个；同一批浏览器逐文件上传 |
| 未终结位置容量 | 全局 100 个，创建批次时预留；不足返回可重试 503，不创建半个批次 |
| 暂存容量 | 全局 4 GiB，统计原文件、解析暂存与异常存储；流式写入预留并核算，不超额接收 |
| 缓冲 | 输入缓冲起始 64 KiB；有效条目分批持久化最多 1,000 条，不收集整文件 |
| 清理扫描 | 每 60 秒及启动恢复时执行；API 操作仍同步校验期限，不因扫描间隔允许过期提交 |
| UI 任务轮询 | 管理页可见时每 1 秒；隐藏时暂停，回到页面立即刷新；终态停止 |
| 等待异常/冲突确认 | 沿用设计 24 小时；不因刷新或重复点击延长 |
| 终态保留 | 完成/失败/取消/过期/中断 7 天，保留原 finishedAt |

原文件 50 MiB 限制按文件内容字节计算；拟允许单文件 multipart 请求额外 1 MiB 协议空间，但不能因此接受超过 50 MiB 的文件。服务器及代理限制必须配合验证，不自动修改目标主机代理。队列/磁盘不足只影响尚未提交任务；在错误反馈中区分资源暂不足与输入非法，保持已有文件和绑定。

JSON 对超长文本和未知字段采用跨缓冲 token 处理，XML 同样限制活跃解析缓冲；100 码点以上的文本作为条目异常，不能因整段 token 未能装入固定缓冲而错误报告整个合法结构损坏。错误列表只保存有限摘要，原始完整文本留在原文件。

### 5.2 SQLite 与一致性

每连接启用外键；采用 WAL，写忙等待上限 5 秒；发布和媒体状态变更通过同一后台写入协调器串行化。迁移及文件发布不把外部文件操作误当作 SQLite 事务。大文件条目插入采用预编译参数命令；业务查询只读已发布状态。

生效引用完整性通过 `(MediaId, ActiveFileId)` 指向绑定关系的延迟外键或等价的数据库约束实现，空生效值表示无生效文件；MediaState 的主动停用标记不会因删除最后一条绑定而丢失。采用真实临时 SQLite 文件验证约束与事务，不只使用 mock。

### 5.3 筛选算法与稳定性

算法版本固定为 `m1-v1`。按整数毫秒计算非空分钟桶；已知媒体时长时只筛选不晚于时长的条目。分钟桶按时间排序；不足一分钟的末桶与其他非空桶同样参与均衡分配。

采用均衡配额反复分配剩余名额，稀疏桶只取实际数量；最后的余数按稳定哈希顺序分配。哈希输入采用明确 UTF-8/整数格式，含算法版本、媒体 ID、文件版本、媒体时长及加载上限；桶内条目用源序号和内部 ID 形成稳定排序键，取配额数量的最小哈希项。禁止使用进程随机化的 `GetHashCode()` 或未固定种子的 Random。

最终按 `(TimeMs, SourceOrdinal)` 排序。实现只保留桶统计和被选候选，不把完整正文加载到筛选内存。用黄金输入/输出验证跨重启一致性、少于桶数的上限、极度稀疏/密集混合及哈希并列时的确定性次序。

### 5.4 播放重试预算

已选集合以紧凑 UTF-8 响应保存在插件私有可清理目录，10 分钟到期；全局有效集合序列化预算 **256 MiB**、最多 **128** 份，触及任一预算时拒绝新集合并返回 503，不提前淘汰有效集合。响应按流式读取输出，不为所有缓存集合保留反序列化内存对象。

请求元信息持久化到 PlaybackRequests；记录认证会话标识的不可逆派生值，不保存原始 token。已有标识即使负载过期仍返回 410，直到会话失效或明确退出得到可靠确认；无法可靠确认退出时保留至会话失效。元信息最多 100,000 条，满额拒绝新请求；已加载浏览器集合不受影响。P1/P6 验证目标版本中认证会话失效的实际检查接口，不能将 WebSocket 断开等同于用户登出。

### 6.3 性能与资源测量

固定测试视频、浏览器版本、视窗、解码模式和硬件加速条件，设备信息仅保存于忽略的原始结果中，公开报告记录可复现的必要规格和结果，不记录主机身份。

默认场景：符合 50 MiB 的 300,000 条合成源数据，长视频档选取 10,000 条，中档同屏 30 条。最大场景：20,000 条加载及 100 条同屏，分别执行相同测量并单独报告，不用默认结果替代。浏览器布局尺寸使用 1440×900 和 390×844；窄屏验证不代表移动浏览器支持。

- 加载热运行 20 次，P95 采用排序后第 19 个值，要求不超过 2 秒；首次冷运行单独记录。每次创建新的播放标识，不能通过命中同一重试缓存伪装加载速度。
- 设置响应与跳转后状态重建各测 20 次，P95 不超过 200 毫秒，排除视频缓冲时间。
- 同一视频关闭/开启弹幕各连续播放 10 分钟，比较视频掉帧占比，增量不超过 1 个百分点；同时确认实际有足量弹幕渲染，不能靠不显示弹幕取得结果。
- 连续进入/退出 20 次，检查活动 Canvas/事件/定时器和请求数恢复基线，记录各轮结束后的堆内存。支持受控 GC 的环境使用相同条件；其他浏览器结合资源计数和内存趋势，不把浏览器不立即归还系统内存直接判为泄漏。
- 默认场景未达目标先定位修复；最大配置出现明显资源或体验问题不得无说明宣称全部合法范围通过。无法修复而需降低上限或改变显示契约时回到设计变更审阅，不擅自下调。
