## 4. 实施顺序与完成条件

本节列出已批准的实施顺序，实际状态见第 1、9 节。获得明确开工授权后按 P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 → P10 推进；各阶段随实现补充对应自动化验证，P9 汇总完整结果。

### P1：验证目标版本 Web 接入

1. 在隔离实例验证固定同源引导、Base URL 根路径及非空路径、公开启用状态、静态资源类型和插件禁用后的安静退出。
2. 实现最小 Web 适配，证明可以取得当前媒体 ID、实际视频元素、播放进度、认证上下文和控制栏/全屏容器；验证直接打开播放页面，无需先进入管理页。
3. 以少量人工构造弹幕验证开关、页面切换、全屏、暂停与跳转；不接入真实业务存储。验证浏览器中的实际播放，不以静态 DOM 插入成功代替。
4. 将通过的接入代码收敛为正式适配模块，去除临时调试入口。保存兼容性验证结果于 `artifacts/m1/web-integration/`。

**完成条件：** Chromium 和 Firefox 自动化均能独立进入播放页并使用最小叠加层，原播放器及登录流程不受影响，入口可撤销。若目标版本契约无法满足已批准设计，停止后续依赖工作并修订设计，不绕过为浏览器扩展、其他插件依赖或 Web fork。

### P2：建立持久化、依赖与发布基础

1. 加入固定 SQLite 依赖和 Danmuku 专用服务注册，沿用现有 .NET 工程约束。
2. 建立设计中的文件、弹幕、媒体状态/绑定、批次/位置/任务/异常、播放请求和结构版本表；用事务及约束实现生效引用完整性，配置主键与分页/时间索引。
3. 实现数据目录解析、首次建库、迁移前一致性备份和失败保留；不通过空库覆盖旧数据恢复。
4. 实现发布意图登记、暂存转正式、提交前后的恢复，以及删除标记与磁盘清理重试；故障注入覆盖各持久化边界。
5. 提前修改 `build/package.py` 的 Danmuku 分支，生成依赖清单，验证 ZIP 能在干净实例创建数据库及读写，不借用构建输出目录或 SDK 缓存。

P2 故障注入按持久化事务结果判定恢复，不能统一要求回到旧生效文件：

| 故障点 | 重启后预期 |
| --- | --- |
| 原文件已暂存或移动，但发布事务未提交 | 原绑定及生效选择不变，任务标记中断；仅清理能够确认属于未完成任务的数据 |
| 发布事务已提交，但成功响应尚未返回 | 保留提交后的文件、条目、绑定及生效选择，任务恢复完成；不清理已发布文件，不重复发布 |
| 进程在提交边界退出，调用方无法判断结果 | 核对持久化事务结果，归入未提交或已提交状态；不出现半份绑定，不以成功响应是否送达决定回滚 |

**完成条件：** SQLite 测试、进程中断恢复与最小插件包加载通过；AgentBridge 包内容与独立性保持不变。

### P3：实现两种格式与异常统计

1. 使用流式 XML 和 JSON 读取，原文件同时写入任务暂存并计算哈希；不使用整文件 DOM 或把 30 万条装入单个集合。
2. 按设计实现秒转毫秒、源 ID 字符串优先、缺失字段默认值及告警统计、模式 1/4/5、100 码点判断、纯文本、附加来源信息和未知字段兼容。
3. 源顺序持久化，按时间和源顺序稳定排序；超出视频时长仍保存，不自动删重复弹幕。
4. 单条异常写入分页明细；正常条目不生成管理明细。整体结构失败、文件/源条目超限、零有效条目按设计拒绝，部分异常等待确认。
5. 创建不含真实用户文本的人工 fixtures 和边界数据生成器；外部样本通过 `DANMUKU_SAMPLE_DIR` 提供，依据设计哈希核对，不提交原样本或固定绝对路径。

**完成条件：** 两种人工样本和边界测试通过；外部真实样本分别完成统计与关键字段核对，结果与设计记录对照，不把两种格式当成完全相同的数据。

### P4：实现导入任务、绑定与替换

1. 创建批次即登记全部位置，实现 PendingUpload/Receiving/Accepted 和终结状态；绑定任务 ID 与位置唯一，重复请求返回已有状态。
2. 实现按列表发布、继续接收后序上传、一键确认单文件/本批异常、取消指定位置和未接收位置、期限收尾及终态 7 天清理。
3. 实现普通首次/追加导入、内容复用、同名后缀和主动停用状态保留。
4. `operation=replace` 持久化 `replaceFileId`，按批准的生效状态表原子提交；B 已存在或 B=A 时优先复用，不误报追加成功为替换完成。
5. 媒体绑定使用版本条件更新；冲突保留暂存，刷新后的 Resume 不丢失替换意图；A 已解除时拒绝继续原替换。
6. 实现失效绑定检查、单个检查和管理员全量检查任务。查询失败与媒体不存在分别处理；不会自动按同名或路径重新绑定。

**完成条件：** 复审提出的替换、空缺上传位置、中断保留场景全部有自动化覆盖；并发、取消、断连、响应丢失与重启均不会产生半份绑定或永久进行中的批次。

### P5：完成管理 API 与权限

1. 实现设计第五章列出的全部管理接口及 DTO；使用管理员认证，下载和引用查询同样受保护，固定公开资源仅采用白名单。
2. 分页默认 50、最多 100；按批次查询同时返回最多 10 个位置摘要，保持任务明细分页，不隐藏尚无任务的位置。
3. 返回阶段百分比、摘要、业务错误码和到期时间；不会把文件读完或数据库尚未提交显示成导入成功。
4. 配置读取/保存沿用 Jellyfin 插件接口，在服务端统一校验上下限与非递减关系，失败不改变旧配置；只对当前用户返回允许的数据。
5. 扩展隔离 HTTP 验证，覆盖管理员、普通用户、受限媒体用户和匿名请求；不能以属性反射测试代替实际授权行为。

**完成条件：** 管理流程可以完全由 HTTP 调用走通，错误与状态契约符合设计，既有 health 与配置兼容性通过。

### P6：实现受限播放集合及重试

1. 服务端读取媒体时长和权限，以配置快照确定加载档位；未知时长取最小档，不接受客户端自报时长作为授权依据。
2. 实现第五节规定的确定性筛选，最多返回配置条数；不传发送者哈希、源路径或完整导入集合。
3. 实现 `playbackId` 与用户、认证会话、媒体绑定，合并同一请求的并发创建；首次建成集合后固定文件版本和配置。
4. 保留有限集合 10 分钟供失败重试；成功播放不依赖缓存存续。到期返回 410，容量不足返回 503，权限撤销与 Web 停用优先于缓存命中。
5. 持久化请求元信息，重启无法恢复的集合明确过期；未失效会话的过期请求标识不被当作新请求重新抽样。

**完成条件：** 分档边界、稳定性、余数分配、重复请求、缓存容量、授权撤销及文件删除竞争测试通过；返回总量及会话隔离可由实际 HTTP 验证。

### P7：完成管理页面与播放器

1. 按四个功能区完成媒体绑定、文件、任务和设置页面，沿用 Jellyfin 管理页与原生 JS/CSS。提供阶段百分比与摘要，只有异常有分页明细，一键跳过不受当前页影响。
2. 显示替换/解除绑定/删除本体的不同影响，只有完整替换提交后显示成功；冲突恢复展示当前状态。
3. 以 Canvas 绘制有限集合，默认滚动周期 8 秒、固定周期 4 秒；用视频时钟计算位置、轨道和可见区，不用墙钟累积播放时间。
4. 原 P7 已实现的三档数量密度将按第 10 节替换为四档动态密度，新增任务不记为已完成；保留 25%/50%/75%/100% 区域、10%–100% 不透明度和 50%–200% 字号缩放；按服务器和用户隔离本地偏好。
5. 无弹幕不提示；加载失败自动提示一次；播放页面提供手动重试并逐次反馈结果，不把单次播放消息放入设置面板。
6. 关闭、跳转、切换视频、退出登录和尺寸变化正确清理或重建；同屏已满直接跳过，不延迟补播，不因跳转增加选定集合。
7. 不为画中画添加渲染功能，仅在可用事件下暂停原页面资源，退出后定位当前进度。

**完成条件：** Chromium/Firefox 浏览器自动化验证全部页面和播放行为，无重复监听、迟到响应覆盖或正常条目全量列表；开始性能测试前具备资源释放测量点。

## 5. 具体实现参数

以下是设计明确留给实施计划的实现参数，随本计划审阅，不修改已冻结的产品限额。资源预算用于防止任务与缓存无限增长，不是性能已通过的承诺。

### 5.1 导入与后台任务

| 参数 | 计划值/行为 |
| --- | --- |
| 未开始上传位置的期限 | 批次创建后 60 分钟；到期记 Expired |
| 单文件接收期限 | 接收开始后 30 分钟，且连续无进展 120 秒即失败；不续传 |
| 接收/解析/发布并发 | 全局接收最多 2 个、解析 1 个、发布写入 1 个；同一批浏览器逐文件上传 |
| 未终结位置容量 | 全局 100 个，创建批次时预留；不足返回可重试 503，不创建半个批次 |
| 暂存容量 | 全局 4 GiB，统计原文件、解析暂存与异常存储；流式写入预留并核算，不超额接收 |
| 缓冲 | 输入缓冲起始 64 KiB；有效条目分批持久化最多 1,000 条，不收集整文件 |
| 清理扫描 | 每 60 秒及启动恢复时执行；API 操作仍同步校验期限，不因扫描间隔允许过期提交 |
| UI 任务轮询 | 管理页可见时每 1 秒；隐藏时暂停，回到页面立即刷新；终态停止 |
| 等待异常/冲突确认 | 沿用设计 24 小时；不因刷新或重复点击延长 |
| 终态保留 | 完成/失败/取消/过期/中断 7 天，保留原 finishedAt |

原文件 50 MiB 限制按文件内容字节计算。实际接口将单个原文件作为请求体流式接收，批次元数据提前登记，不使用 multipart，也不需要原拟议的额外 1 MiB 协议空间；文件限额与批次契约不变。服务器及代理限制必须配合验证，不自动修改目标主机代理。队列/磁盘不足只影响尚未提交任务；在错误反馈中区分资源暂不足与输入非法，保持已有文件和绑定。

JSON 对超长文本和未知字段采用跨缓冲 token 处理，XML 同样限制活跃解析缓冲；100 码点以上的文本作为条目异常，不能因整段 token 未能装入固定缓冲而错误报告整个合法结构损坏。错误列表只保存有限摘要，原始完整文本留在原文件。

### 5.2 SQLite 与一致性

每连接启用外键；采用 WAL，写忙等待上限 5 秒；发布和媒体状态变更通过同一后台写入协调器串行化。迁移及文件发布不把外部文件操作误当作 SQLite 事务。大文件条目插入采用预编译参数命令；业务查询只读已发布状态。

生效引用完整性通过 `(MediaId, ActiveFileId)` 指向绑定关系的延迟外键或等价的数据库约束实现，空生效值表示无生效文件；MediaState 的主动停用标记不会因删除最后一条绑定而丢失。采用真实临时 SQLite 文件验证约束与事务，不只使用 mock。

### 5.3 筛选算法与稳定性

算法版本固定为 `m1-v1`。按整数毫秒计算非空分钟桶；已知媒体时长时只筛选不晚于时长的条目。分钟桶按时间排序；不足一分钟的末桶与其他非空桶同样参与均衡分配。

采用均衡配额反复分配剩余名额，稀疏桶只取实际数量；最后的余数按稳定哈希顺序分配。哈希输入采用明确 UTF-8/整数格式，含算法版本、媒体 ID、文件版本、媒体时长及加载上限；桶内条目用源序号和内部 ID 形成稳定排序键，取配额数量的最小哈希项。禁止使用进程随机化的 `GetHashCode()` 或未固定种子的 Random。

实现冻结格式：上述字符串按 UTF-8 字节长度（Int32 小端）前缀编码，时长（未知为 -1）和上限按 Int64 小端编码，一次 SHA-256 得到种子。对种子和两个 Int64 小端字段使用 FNV-1a 64，再经固定 fmix64 终混合得到抽样键；桶字段为分钟索引/-1，条目字段为源序号/内部 ID。抽样键不用于认证或内容校验，后两者仍使用 SHA-256。该选择属于稳定哈希的实现细节，不改变分桶、配额或总量契约。

最终按 `(TimeMs, SourceOrdinal)` 排序。实现只保留桶统计和被选候选，不把完整正文加载到筛选内存。用黄金输入/输出验证跨重启一致性、少于桶数的上限、极度稀疏/密集混合及哈希并列时的确定性次序。

### 5.4 播放重试预算

已选集合以紧凑 UTF-8 响应保存在插件私有可清理目录，10 分钟到期；全局有效集合序列化预算 **256 MiB**、最多 **128** 份，触及任一预算时拒绝新集合并返回 503，不提前淘汰有效集合。响应按流式读取输出，不为所有缓存集合保留反序列化内存对象。

请求元信息持久化到 PlaybackRequests；记录认证会话标识的不可逆派生值，不保存原始 token。已有标识即使负载过期仍返回 410，直到会话失效或明确退出得到可靠确认；无法可靠确认退出时保留至会话失效。元信息最多 100,000 条，满额拒绝新请求；已加载浏览器集合不受影响。P1/P6 验证目标版本中认证会话失效的实际检查接口，不能将 WebSocket 断开等同于用户登出。

### 10.4 D2：纯布局、测量与确定性重建

**占用和字形。** 以 CSS 像素计算。采用 `textBaseline=alphabetic` 并把绘制起点转换到包含描边的包围盒内；宽取文字 advance 与实际左右边界所需宽度的较大者，再包含两侧描边。行高不小于 `ceil(1.25 × 字号)`，也不小于字形上下边界加描边的高度。优先使用有效的 Canvas 文本边界；缺失或非有限时回退字体边界，再回退字号比例，并在目标 Chromium／Firefox 实际验证中英混合及 emoji 不侵入相邻行。沿用 2 CSS 像素描边，不按密度改变字重、速度或透明度。测量回退若不能满足包围盒约束，先修复，不能以理论尺寸测试替代真实字形测试。

`a=min(w,W)×h`，低／中在准入时预留面积，结束后释放；所有模式和未完全进入画面的已接纳条目合计。先释放 `end≤t` 的条目再处理时刻 `t` 的新条目。检查数量与预算后才选位置，失败不改变活跃列表及面积；结束时间使用现有滚动 8 秒、固定 4 秒。按输入索引打破相同时间的并列，拒绝条目不重排、不另入队。

**轨道与重叠。** 使用各条目实际占用高从上往下枚举合法位置，底部模式反向枚举；候选位置步进沿用 `max(8,h)` 的确定性规则，各档相同。前三档检查共存期间的二维包围盒相交；滚动线性轨迹通过重叠时间段端点／区间判断追尾，不能把顶部、底部与滚动交叉遗漏。横向安全留白固定 12 CSS 像素、各档相同，面积不额外把该安全距离当作文字宽度。重叠档固定条目只避让固定条目；滚动优先找无碰撞位置，无可用位置时选与活跃滚动纵向交叠数量最少的候选，并列从上次复用位置之后循环选择。复用游标属于确定性布局状态，重建必须还原，不使用随机数。

**时间重建。** 将文字测量与排布决策分离。对一个“集合＋配置快照＋画面几何＋区域＋字号＋密度”键维护最多一份布局决策索引，按源事件顺序计算接纳／拒绝和 y 位置。连续播放和 seek 使用同一决策，不以浏览器掉帧时批量到达的墙钟时间重新排布。索引只推进到所需进度；此前已计算区间直接复用，尚未计算的前缀从最后完整事件状态继续处理。向后 seek 使用已计算决策取出该时刻尚未结束的条目；设置／几何改变废弃旧键，重演新条件的前缀，不用“只重播最近 8 秒”代替完整决策。

- 最多 20,000 条条目，使用定长数值数组保存测量／结果，不复制文本或保存逐帧快照；每个播放的新增测量和索引数值缓冲总预算 2 MiB，活跃状态最多 600 条，仅保留一组设置。按需重算换取空间，不为所有档位／视窗缓存副本。
- 重演单批最多 256 个事件或 4 毫秒，两者先到即让出主线程；同一个时间戳的组可分批计算但只发布完整目标状态。用户再次改设置、退出或换视频时取消旧任务，使用代次标识防止迟到结果覆盖。
- 算法检查阶段先测最大 20,000 条、600 活跃、长视频末尾首次重建和换设置的成本。分批执行本身不等于达到 200 毫秒，计时包含全部批次等待；未达标需在本阶段优化有界索引与碰撞查找，不先宣称通过或提高预算掩盖问题。
- 不透明度只重绘，不改变布局键；开关关闭清空画面并停止动画，重新开启按当前进度恢复。退出、换视频和注销释放全部索引、任务与文字引用。

**异步完成测试契约。** 播放器提供只读的操作状态及完成事件，测试不再用单个 RAF 或无身份的 `lastRebuildMs` 判断重建完成。每条状态至少包含 `playbackId`、`operationId`、`generation`、布局键标识、触发原因、`targetTimeMs`、实际提交的 `committedTimeMs`、`phase`、起始／提交的单调时钟时间。`operationId` 对应一次加载／设置／seek，`generation` 对应其有效布局任务；原因相同、进度相近或耗时更新均不能代替身份匹配。该观察接口只含标识、数值和状态，不泄露弹幕文本，也不新增远端管理 API。

- 状态至少区分 `computing`、`cancelled`、`failed`、`committed`。仅在测量完成、目标所需前缀全部处理、活跃集合／预算与 Canvas 完整绘制提交后发布 `committed`；期间的动画帧、一次分批回调、响应接收及部分布局都不是完成。画面当前没有可见条目时，完成当前时间的布局并提交空画面也可就绪，不等未来弹幕。
- 在用户操作和请求发出前安装测试观察者，操作触发时同步建立身份，状态查询与事件使用相同身份，避免极快完成导致漏听。测试等待精确匹配的播放／操作／有效代次，失败或被取代记为失败／取消，不能回退读取上一轮的完成时间，也不能把缺样本填为零。每次性能操作单独串行执行；取消竞争是独立功能用例。
- seek 在 `seeking` 时作废旧目标，`seeked` 时绑定最终视频进度并完成对应有效代次的提交。即使计算提前完成，也要在该次 `seeked` 后确认目标并发布匹配的提交状态；测试排除视频缓冲，单独使用 `seeked` 时间作为计时起点。播放中的重建记录最终实际提交进度，提交前将事件前缀推进到该帧视频时间，不以不断移动的目标创建无穷新代次。
- 不透明度等仅重绘操作也通过相同操作身份在重绘提交后完成；关闭通过清空并停止绘制后的提交完成。切视频、注销及新操作取消旧任务后，旧任务不得再转为 `committed` 或修改新状态。只保留当前状态和必要的终态快照，不存无界历史；测试可在自己的隔离结果中收集事件序列。

**验证／完成条件：**用注入尺寸的独立测试覆盖预算边界与释放、混合模式、600 上限、稳定突发、长文本、零尺寸、重叠复用和连续／seek 完全一致；另以真实浏览器校验测量和重建计时。测试应断言已接纳索引、位置、占用与生命周期，而非只比对实现常量。D2 性能失败先解决，不进入整套长时矩阵。

| 指标 | 起点 | 终点及必含工作 |
| --- | --- | --- |
| 加载就绪 | 该次真实播放器加载请求发出 | 该响应绑定的播放／操作／有效代次提交当前进度画面；含请求、解析、文字测量、事件前缀重演、所有批次等待和绘制提交，无可见条目时以空画面就绪结束 |
| 设置响应 | 用户输入／change 被处理之前记录的时刻 | 对应操作有效代次完成新设置的布局和画面提交；不以第一帧、控件值改变或上轮指标更新结束 |
| seek 响应 | 本次视频 `seeked` 事件时刻 | 最终目标进度对应的有效代次完成提交；不包含此前视频缓冲，但包含此后必要测量、分批等待和提交，不能借用此前目标的完成信号 |

加载每次使用新 `playbackId`，实际走同一播放器解析／布局／提交管线，验证返回条数及已就绪进度；首次冷运行单列，另采 20 次热运行，禁止裸 HTTP 耗时替代加载就绪，也禁止复用同一重试缓存。seek 的 20 次样本除普通定位外，必须包含长视频尾部尚未构建前缀的情况；设置样本包含使布局键失效的真实重建。保存每个样本的播放／操作／代次、目标／提交进度、起止时间及终态，以便核对不存在上一轮信号污染。`seeked` 和一次 RAF 都只表示视频或浏览器调度事件，本身不是布局就绪证据。

**可复现负载：**保留默认筛选压力样本；为最高负载另生成不超过 50 MiB、恰好 20,000 条有效数据的已绑定隔离样本，保证加载 20,000 条后不受二次抽样稀释。将部分滚动条目以每秒约 80 条连续分布至少 60 秒，另分布尾部突发和混合固定条目；到达上限后自然跳过，不能绕过保护逻辑强塞。目标要求活跃峰值达到 600，至少有连续 30 秒采样不低于 570；视频仍按真实时钟播放。若实际达不到，先查样本、计时和排布原因，不把场景记为最高负载通过。样本种子、哈希、时间分布、进入密集段的时刻均记录，长视频末尾还需验证首次无索引 seek。

**串行与恢复：**设置 `DOTNET_PROCESSOR_COUNT=1`、`MSBUILDDISABLENODEREUSE=1`、`UseSharedCompilation=false`，单一重度任务占用一个可用逻辑 CPU。隔离 Jellyfin 容器限 1 CPU／1 GiB；浏览器一次仅一个引擎／场景，流式生成大样本，不并跑多个编译或浏览器。所有服务测试固定 `127.0.0.1:18096`；只暂停本仓库开发服务，finally 恢复先前状态，不自动换端口、不停止其他项目。

结果写入 `artifacts/m1/density/` 或现有集成测试忽略目录，包含源码／包哈希、版本、数值缓冲、就绪／重建耗时、真实活跃时序、拒绝原因和掉帧。CI 普通触发运行纯布局及双浏览器功能，长时矩阵仍由 performance 入口和 workflow_dispatch 显式执行；提交前本地完成对应矩阵。CI 超时如不足，按实测时长调整并说明，不删覆盖缩短耗时。性能不达标先修复，不擅自降低已确认保护上限。
