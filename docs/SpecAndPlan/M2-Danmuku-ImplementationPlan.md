## 3. 实施契约

本节具体化已批准设计，已随计划复审通过；实现及验收须逐项满足以下契约。

### 3.1 持久化、引用与迁移

1. 新增 `CombinePlans`：`PlanId`、`MediaId`、`Name`、`Version`、创建／更新时间。`PlanId` 为不可变 UUID；同一媒体下裁剪首尾空白后的名称以 ordinal、区分大小写比较并唯一，长度按 Unicode 码点检查。
2. 新增 `CombineSegments`：`PlanId`、`Ordinal`、`FileId`、`SourceStartMs`、可空 `SourceEndMs`、`TargetStartMs`。主键为方案与行序号；按方案级联删除，文件引用使用 RESTRICT；建立按 `FileId` 查引用的索引。源结束空值表示到末尾，包含最后一条。完全重复行由规范化字段组合检查，不做弹幕去重。
3. `MediaState` 增加 `ActivePlanId`。数据库约束保证 `ActiveFileId` 与 `ActivePlanId` 最多一个非空，停用时均为空；复合外键保证生效方案属于同一媒体，保留生效单文件必须属于绑定集合的约束。保留无生效项但未主动停用的原始状态，不把它误判为主动停用。
4. `PlaybackRequests` 增加来源类型、方案 ID 与方案版本快照。历史播放元数据不以指向可删除方案的强制外键阻止清理；缓存保存完整已选渲染条目，方案删除不破坏现有缓存。
5. v4→v5 在一致性备份后执行必要表重建；保留原文件、Comments、导入批次／任务、MediaBindings、媒体版本、生效选择、停用和检查状态。无方案的旧数据 `ActivePlanId` 为空；新库按 0→5 顺序迁移。
6. 数据约束检查：外键、非负整数时间、结束晚于开始、非负版本、唯一名称及生效类型互斥；跨行数量上限和文件 Published 状态由服务事务校验。标记删除中的文件不得新增方案引用，文件删除标记与最终清理均纳入方案引用检查。
7. 文件列表引用统计覆盖单文件绑定与方案引用；“仅未绑定”筛选更新为无任何引用，并以“仅未引用”文案解释。引用详情区分媒体单文件绑定与方案，方案含同文件多行时显示一个方案引用及片段数量，不以单文件绑定数作为可删除判据。

### 3.2 名称、时间与统计

- 新建编辑器预填当前媒体中最小可用正整数后缀 `combine-N`，不预占名称。保存仍校验唯一性；并发占用时返回名称冲突、保留输入并提供新的可用名称，不静默改掉用户手动名称。删除后的空缺编号可以复用。
- 方案须有 1–50 行、总选中条数为 1–1,000,000；每媒体至多 20 个。计数包含重复实例及视频时长外条目，逐行统计和总数使用一致数据快照，保存时重新校验，不信任浏览器统计。
- 时间编辑统一接受 `MM:SS[.fff]` 或 `HH:MM:SS[.fff]`，支持超过一小时及毫秒，结束另有“到文件末尾”选择。秒字段 0–59、小时格式的分钟字段 0–59，拒绝负数、非有限值及小数毫秒。
- API 使用整数毫秒；可编辑及输出时间限定为 JavaScript 安全整数范围，服务端用 checked 整数运算验证 `目标起点 + (源时间 − 源开始)`。选中的实际条目或显式区间终点不可精确表示时拒绝该配置，不溢出、取模或静默舍入；源文件本体仍保留。
- 范围 `[start,end)`；末尾空值不使用 `LastCommentTimeMs+1` 代替，避免边界溢出。默认零起点、到末尾、目标零；源起点变化不改目标起点。
- 显式源结束可以晚于最后弹幕，不据此扩大选中条数；源起点晚于末条时显示零条。到末尾的映射展示“最后一条预计出现在…”，不伪造视频区间终点；空行显示无选中条目。
- 已知视频时长沿用 M1 的 `TimeMs <= durationMs` 口径，严格大于时长的条目不参与抽样额度。时长未知保留候选并提示无法检查；全部候选在视频范围外时保存允许、播放为空。

### 3.3 方案版本与媒体版本（R2）

| 操作 | 校验与递增规则 |
| --- | --- |
| 新建，仅保存 | 校验媒体存在、名称、20 个上限及来源，方案版本从 1 开始；必要时建立空媒体状态，不改变生效选择，已有媒体版本不递增 |
| 编辑，仅保存 | 校验方案预期版本，成功递增方案版本；不写回客户端保存的生效选择。若编辑对象当前生效，则同时递增媒体版本，使旧导入或启用请求感知生效内容变化 |
| 保存并启用 | 校验媒体预期版本；已有方案另校验方案预期版本；内容、引用及选择同一事务提交，分别递增方案版本和媒体版本 |
| 单文件／方案切换、停用 | 校验并递增媒体版本；启用方案同时校验目标方案预期版本，避免启用已被另一页面修改的内容 |
| 删除方案 | 校验方案版本及媒体版本，读取事务内实际生效状态；非生效删除不变更媒体选择或版本；生效删除必须明确替代项或停用并递增媒体版本 |
| 新版绑定集合写入 | 校验媒体预期版本；preserve 保留事务内当前选择，set 使用完整目标选择且启用方案时校验目标方案版本；绑定与选择一起提交、媒体版本递增，方案内容／版本不变 |
| 原绑定及追加／替换发布 | 保留既有媒体版本检查和递增；方案启用／生效内容变更使旧发布进入原冲突恢复流程，不覆盖方案选择 |

- 所有预期版本检查和对应写入在同一事务完成。失败或冲突不提交本次方案内容、引用或生效状态；UI 保留输入，提示核对最新版本，不自动以新版本重放旧请求。
- 单文件追加首次自动启用必须额外满足当前无生效方案；已有方案、已有单文件或主动停用时保留原选择。替换只操作指定单文件绑定；当前方案保持，方案来源不被替换。
- 仅保存非生效方案不要求媒体版本仍与打开编辑器时一致，但必须重新确认媒体存在及所有输入有效。并发修改生效选择不被该保存恢复。
- 保存响应丢失时先读取方案最新版本及内容确认结果，不盲目重试新建或启用。编辑器的新建方案 ID 由客户端生成 UUID 并复用，已存在 ID 返回可核对的冲突，不另建重名副本。

### 3.4 失效媒体清理（R1）

- 全量检查的媒体集合为单文件绑定与方案所属媒体的去重并集；异常列表同样覆盖两类，显示 Missing 与 CheckFailed 的区别。保留按媒体 ID 管理的入口，不依赖 Jellyfin 仍能搜索到该视频。
- 失效详情可读取方案及来源引用；视频标题不可得时展示媒体 ID 和失效提示。禁止新增、编辑保存、启用，允许管理员显式删除方案；删除当前生效方案必须同时明确停用，不允许切到另一生效项。
- CheckFailed 不当作 Missing，不自动删数据或迁移；管理员仍可执行不依赖媒体存在的显式删除与停用，禁用新增和启用并提供重新检查入口。清理继续校验版本与原子性。
- 清理方案仅解除其片段引用，其他媒体和方案不变，文件本体保留。失效状态或仅一次查询错误不能触发自动清理。

### 3.5 管理接口与兼容入口

接口均在 `/Danmuku` 下并使用管理员策略，数据分页沿用默认 50／最多 100；50 行片段随单个方案返回，不返回百万条弹幕。保存请求体设有限上界（计划 128 KiB），拒绝额外巨量行而非先展开处理。

| 接口（拟定） | 契约 |
| --- | --- |
| `GET Media/{id}/CombinePlans` | 方案摘要、当前生效项、媒体版本和可用默认名称；失效媒体也可读取 |
| `GET Media/{id}/CombinePlans/{planId}` | 名称、片段、方案版本、媒体状态；校验归属 |
| `POST Media/{id}/CombinePlans/Preview` | 草稿片段统计、映射区间、超时长条数和告警；无写入，不预占名称 |
| `POST Media/{id}/CombinePlans` | 新建 UUID、名称、片段、是否启用和启用时媒体预期版本 |
| `PUT Media/{id}/CombinePlans/{planId}` | 内容及方案预期版本，启用时附媒体预期版本 |
| `POST Media/{id}/CombinePlans/{planId}/Delete` | 方案／媒体预期版本，以及必要的明确替代项或停用；事务删除 |
| `PUT Media/{id}/Bindings`（扩展） | `expectedVersion`、完整 `fileIds`、`selectionIntent=preserve/set`；set 附完整 selection，preserve 不附目标选择 |
| `PUT Media/{id}/Selection` | `kind=file/plan/disabled`、目标 ID、媒体预期版本及目标方案版本 |
| `GET Files/{id}/References` | 分页列出单文件与方案引用、媒体状态及片段数 |

- 原绑定查询扩展 `ActivePlanId`，新增完整选择对象；独立切换使用 Selection。新版 Bindings 请求增加 `selectionIntent`：preserve 表示保留事务内当前生效选择（包括方案、单文件、停用和未选择状态）；set 必须提供 `selection={kind:file/plan/disabled,id,expectedPlanVersion}`，字段按类型校验。新版请求不得同时提交旧 `activeFileId`，防止双重语义。
- preserve 在同一事务校验媒体预期版本、文件可用性并更新完整绑定集合，保留方案 ID、生效类型、方案版本与片段。若请求移除当前生效单文件，拒绝并要求管理员明确替代项或停用，不能保留悬空引用。set 同时校验替代文件属于新绑定集合、方案归属及目标方案版本，绑定与选择一起提交；任一冲突均整体失败。
- 新版页面“绑定已有文件”和“解除非生效单文件绑定”发送 preserve；方案生效时所有单文件解绑均不影响该方案来源。解除当前生效单文件时，页面要求明确选择替代单文件／方案或停用，发送 set。失效／检查失败媒体禁止新增绑定或启用，只允许依照既有规则移除绑定、保留既有方案选择或明确停用，不借 preserve 新增可用性绕过。
- 缺少 `selectionIntent` 的旧格式仍按原单文件／停用契约处理；当前为方案则返回可识别冲突要求刷新，绝不把旧 `activeFileId=null` 当作停用。刷新后的新版管理页必须能发送 preserve 完成增删绑定，不持续陷入旧格式冲突。
- 旧单文件文件列表、导入接口继续工作；旧查询兼容字段不作为“无方案引用”的证明。新的删除错误提示包含两类引用。
- 业务错误沿用 401／403／404／409／422／503 语义，超大请求 413。区分名称冲突、方案版本冲突、媒体版本冲突、来源不可用、规模超限和媒体检查失败；前端按代码处理。
- 前端统计采用短防抖、取消旧请求和媒体／编辑代次校验；切换媒体、保存或关闭编辑后迟到响应不得改写当前界面。无须后台持久化统计任务。

### 3.6 合并抽样与播放快照

- 不生成新的原始文件或复制全部标准化条目。读取方案及全部片段，在同一数据库快照内检查全部来源 Published 且数据可读；缺少来源必须报错，不能过滤 JOIN 后悄悄播放剩余文件。
- 候选身份为 `(片段序号, CommentId)`；同一源条目被多个片段选中时生成不同实例。播放条目使用包含片段身份的字符串 ID，不能沿用以 CommentId 为唯一键的字典覆盖重复实例。
- 先按源范围筛选并映射，再按目标分钟统计并统一分配 M1 风格的分钟配额；种子包含合并算法版本、媒体 ID、方案 ID／版本、视频时长和加载额度。稳定排序为目标时间、片段行序、源条目顺序，再用内部 ID 兜底。
- 最多 50 个带参数的范围查询，流式读取数值候选；不把百万条文本装入内存。分钟统计最多与候选数同阶；为有配额分钟维护总容量不超过加载额度的优先队列，仅对选中项分批读取文本并按实例还原。实现中记录候选扫描次数，避免为每个分钟全表重复扫描。
- 在现有串行创建门禁和写协调框架内完成一致快照与缓存登记，支持取消，统计与保存不并发堆积无界工作。复用现有缓存 10 分钟、256 MiB／128 集合／100,000 请求元数据预算，不新建长期方案版本全文缓存。
- 播放响应新增来源类型及方案版本，单文件 FileId 保留。首次成功建立集合前失败可按重试时的状态重建；成功后相同播放 ID 固定集合、配置与方案版本，不受修改、删除或停用影响。重启／过期沿用原 410 行为，不用旧 ID 重抽。
- 不把来源详情、发送者等元信息返回普通播放器；每次请求仍通过现有用户、会话和媒体权限检查。

### 3.7 滚动速度、资源升级与页面

- 偏好新增 `scrollSpeed`，0.5–2.0、0.1 步长、默认 1.0；缺失／非法值回退 1.0，不重置密度、区域、字号、透明度或开关。范围输入用整数档位映射，避免浮点累加漂移。

- 调速取消上一代重建，按当前视频时间重新排布；保留原分批调度、确定性准入、面积／数量预算与防碰撞规则。同设置同时间的连续播放和 seek 重建一致，0.5× 时不可漏掉 8–16 秒前仍活跃的弹幕。
- 新旧 bootstrap／播放器／布局混合缓存时执行同源同版本依赖门禁、共享加载 Promise、失败清理；未知契约让弹幕走失败提示，不影响原视频和字幕。旧客户端请求新服务时返回可识别契约不匹配，刷新后可恢复。
- 管理页保留四分区、原搜索分页、导入异常确认和配置异步保护；新增方案编辑、自动名称、行排序、范围复制与撤销。未保存离开确认、统计代次、保存快照、服务器校验错误均覆盖。
- checkbox、开关等保留原生 input 的可访问语义和焦点；样式限定管理页根元素，采用 Jellyfin 主题变量与可读回退色，不加载第三方 UI、字体或 CDN。桌面表格优先，窄屏局部滚动。

- 功能矩阵：根路径和 `/jellyfin` × Chromium／Firefox。正式 Chrome／Edge 与实际 Firefox 版本由人工阶段记录，自动化引擎不能替代真实浏览器体验。

- CI 下游一律调用 Python 驱动，绝不调用会打包的本地 shell 包装；每份结果记录所下载 ZIP 的 SHA-256。Release 草稿继续依赖包含 M1/M2 的常规集成成功，性能仍不是发布门禁；本轮不实际推送或发布。
- 手动 performance／all 的性能 job 改为显式分组矩阵：24 个 M2 组（路径 × 视窗 × 配置 × 速度），另 2 个 M1 单文件基线组（根路径、`/jellyfin`，各运行原默认／最大两视窗矩阵）。`max-parallel: 1`、`fail-fast: false`，单组超时保留 150 分钟；每组在独立 runner 校验同次包并串行运行，不缩减任何组的关闭／开启各 10 分钟测量。M2 新增 `--performance-group <组ID>`，只执行清单中指定的完整组；未提供组 ID 的本地入口仍按该路径清单逐组执行。
- 24 个 M2 组仅掉帧采样就至少约 480 分钟，总运行还包含基线、准备和短操作，不能承诺在原单个 150 分钟 job 内完成。分组延长整体耗时而不降低矩阵；同一 runner 不并发构建或浏览器。all 的常规任务和性能任务在各自 runner 执行。
- 共享组清单由驱动与测试读取，结果包含组 ID、参数、包哈希、测量数量及完整／失败状态；末尾汇总 job 即使上游失败也收集结果，对缺失、取消、失败、包哈希不一致或测量不足的组判定不完整／失败，只有 26 组全部合格才能报告全套性能通过。局部重跑须在同次 workflow 的相同包基线上核对汇总，不混用其他提交成绩。
- 常规及性能上传均使用 `if: always()` 和明确文件白名单，保留原 `artifacts/m1/integration/` 证据，新增 M2 的 `*-results.json`、`*-browser.json`、`*-performance.json`、`performance-progress.json`、`*-failure.json`、`server.log` 及必要 `.png`，按实际子目录列举。artifact 名包含套件／组 ID，避免分组互相覆盖；禁止直接上传整个 `artifacts/m2/`，尤其不上传 credentials、token、config、数据库、完整 media 或人工夹具状态目录。结果／日志生成阶段也不得写入登录秘密。
- 本地静态校验工作流语法、各事件分派、发布依赖、artifact 白名单及 Python 参数；驱动以故意失败用例验证非零退出码和失败证据。远端路由、artifact 上传和完整分组运行只有实际发生后才记录通过；未执行时明确标记未验证，不因本地通过宣称远端 CI 成功。

前置：P7、P8 已通过。P7 新增并演练 `tests/integration/m2-manual.py`，不复用自动化驱动退出即 down 的生命周期。下列入口均待实施，目前不可执行；工具只使用已测包，不重新构建。

1. prepare 创建唯一 `jellyfin-forge-m2-manual-<id>` 会话及独立 `artifacts/m2/manual/<id>/` config/cache/media、Compose 和状态清单，生成 V1／V2 与 A／B／C、管理员和普通用户。样本包含起点、终点前 1 ms、终点、重复文本和源 12:00 标记，V1 覆盖 30 分钟以上；媒体只读挂载。只准备夹具，不预先执行用户验收操作。

3. prepare 成功后退出进程但保持容器运行，直到用户结束验收再显式 finish；不会执行自动化 context manager 的退出清理。交接提供地址、session ID、V1/V2 标识、样本路径与步骤；账号信息保存在会话目录 `credentials.json`，权限 0600，告知本地读取位置，不写入受版本管理文档或 CI artifact。
